## Алгоритм

### Шаг 1 — Определить паттерн(ы)

Прочитай `references/patterns.md` и сопоставь запрос пользователя:

| Паттерн | Когда выбирать |
|---------|----------------|
| **P1a** | Добавить раздел с обсуждением к объекту; чат всегда виден когда объект не новый — минимальный вариант |
| **P1b** | Добавить раздел с чатом + кнопка «Открыть чат»; пользователь явно активирует переписку |
| **P2** | Добавить пункты меню управления СВ в навигацию приложения (одноразовая настройка) |
| **P3** | Включить плавающий виджет веб-чата в приложении (одноразовая настройка) |

Пользователь может запросить несколько паттернов одновременно — применяй последовательно.  
P1a и P1b взаимоисключают друг друга для одного объекта.

### Шаг 2a — Анализ формы объекта (P1a / P1b)

Параллельно с шагом 1 запусти:

```bash
python3 .claude/skills/xbsl-form-info/scripts/form_info.py --name <ИмяОбъекта> --root .
```

Из результата:
- `existing_forms["ФормаОбъекта"]` → путь к YAML формы. Если ключа нет — предложи сначала создать форму через `xbsl-form-add`, затем продолжить.
- Прочитай найденный YAML формы и определи тип шаблона:
  - `Тип: ШаблонФормыСРазделами` → вставляем в `ДополнительныеРазделы`
  - `Тип: ПроизвольныйШаблонФормы` → предупреди пользователя, что `ДополнительныеРазделы` недоступны; предложи добавить компонент вручную в нужное место `Содержимое`
- Проверь, есть ли уже `КомпонентОбсуждения` в YAML формы — если да, сообщи и остановись.
- Проверь, есть ли секция `ДополнительныеРазделы` в блоке `Содержимое` — она может отсутствовать даже при `ШаблонФормыСРазделами`.

### Шаг 2b — Анализ компонента приложения (P2 / P3)

Запусти:

```bash
python3 .claude/skills/xbsl-collab-add/scripts/find_app.py --root .
```

Из результата:
- `status: not_found` → сообщи, что компонент `СтандартноеКлиентскоеПриложениеСРазделами` не найден; предложи проверить корень проекта.
- `has_interaction_group: true` → P2 уже применён; сообщи и пропусти P2.
- `has_web_chat: true` → P3 уже применён; сообщи и пропусти P3.
- `nav_is_inline: false` → для P2 редактировать файл `nav_yaml`.
- `nav_is_inline: true` → для P2 редактировать `yaml_path` (блок `КомандныйИнтерфейсПанелиНавигации`).

### Шаг 3 — Dry-run: показать план

Опиши конкретные изменения для каждого выбранного паттерна:

**P1a:**
- `{ФормаОбъекта}.yaml` — добавить в `ДополнительныеРазделы` группу «Обсуждение» с `КомпонентОбсуждения`
- `{ФормаОбъекта}.xbsl` — создать или дополнить: метод `ПослеЧтения` с `УстановитьКонтекстОбсуждения(КлючОбъекта)`

**P1b:**
- `{ФормаОбъекта}.yaml` — добавить в `ДополнительныеРазделы` группу «Чат» с `КомпонентОбсуждения` + `Надпись`; в `Свойства` — реквизит `ПоказатьЧат: Булево`
- `{ФормаОбъекта}.xbsl` — создать или дополнить: методы `ПослеЧтения` и `НадписьПоказатьЧатПриНажатии`

**P2:**
- `{nav_yaml или yaml_path}` — добавить в конец `Элементы` группу «Система взаимодействия» с 4 командами управления СВ

**P3:**
- `{yaml_path}` — добавить `ВебЧат: {Использовать: Истина, ...}` в блок `Наследует` после строки `Тип: СтандартноеКлиентскоеПриложениеСРазделами`
- `{xbsl_path}` — создать или дополнить: метод `ВебЧатПриПолученииДанных`

Запроси подтверждение у пользователя.

### Шаг 4 — Apply (только после подтверждения)

Шаблоны YAML и XBSL — в `references/patterns.md`.

**P1a:**
1. В YAML формы: если секция `ДополнительныеРазделы` существует — добавь группу «Обсуждение» в её конец. Если нет — добавь `ДополнительныеРазделы:` после закрытия блока `ОсновнойРаздел`.
2. В `.xbsl` формы: если файл существует — дополни методом `ПослеЧтения` в конец. Если нет — создай файл. Если метод `ПослеЧтения` уже есть — добавь строки `если ... УстановитьКонтекстОбсуждения` внутрь существующего метода.

**P1b:**
1. В YAML формы: добавь группу «Чат» в `ДополнительныеРазделы` (как в P1a). В секцию `Свойства` добавь реквизит `ПоказатьЧат: Булево`. Если секции `Свойства` нет — создай её.
2. В `.xbsl` формы: добавь оба метода (`ПослеЧтения` и `НадписьПоказатьЧатПриНажатии`).

**P2:**
1. Если `nav_is_inline: false`: открой файл `nav_yaml`, найди корневую секцию `Элементы:` и добавь группу «Система взаимодействия» в её конец.
2. Если `nav_is_inline: true`: открой YAML приложения (`yaml_path`), найди секцию `КомандныйИнтерфейсПанелиНавигации:` → `Элементы:` и добавь группу в конец (с отступом +8 от корня файла).

**P3:**
1. В YAML приложения: найди строку `Тип: СтандартноеКлиентскоеПриложениеСРазделами` и добавь сразу после неё (с отступом 4):
   ```yaml
       ВебЧат:
           Использовать: Истина
           ПриПолученииДанныхПользователя: ВебЧатПриПолученииДанных
   ```
2. В `.xbsl` приложения: если файл существует — добавь метод `ВебЧатПриПолученииДанных` в конец. Если нет — создай файл с методом. Добавь строку `импорт <Подсистема>` с модулем `ПользователиКлиентИСервер` — или укажи пользователю подставить нужный импорт.

### Шаг 5 — Итог

Перечисли созданные и изменённые файлы с кратким описанием каждого изменения.  
Для P2 и P3: напомни, что изменения вступят в силу после перезапуска приложения на сервере.
