# Спецификация: SoapСервис

## Назначение

Platform facts:

- `ВидЭлемента: SoapСервис` публикует SOAP endpoint приложения.
- `ИмяСервиса` задает `definitions.name` WSDL-описания; если поле не указано,
  используется имя элемента проекта.
- `ПространствоИменСервиса` задает `definitions.targetNamespace`.
- `Обработчики[]` описывает операции сервиса: `Имя` — имя операции,
  `Метод` — имя метода в одноименном модуле сервиса.
- Платформа формирует WSDL-контракт по YAML и модулю сервиса, включая секцию
  ошибок из `Ошибки` сервиса и `Ошибки` отдельных обработчиков.
- После добавления сервиса создается серверный тип `{ИмяSoapСервиса}`.

Local conventions:

- Для нового сервиса skill создает только файлы проекта разработчика:
  `<Имя>.yaml` и `<Имя>.xbsl`.
- Не создавай WSDL/XSD-файлы для SOAP-сервиса: для сервиса они являются
  результатом платформенной генерации, а не входным companion.
- Имена методов обработчиков задавай латиницей, так как в модуле сервиса
  запрещены кириллические имена обработчиков.

## YAML

Required:

```yaml
ВидЭлемента: SoapСервис
Ид: <UUID>
Имя: <ИмяSoapСервиса>
ОбластьВидимости: ВПодсистеме
ПространствоИменСервиса: https://example.com/<namespace>
КорневойUrl: /<resource>
Обработчики:
    -
        Имя: GetOrder
        Метод: GetOrder
```

Optional:

- `ИмяСервиса` задает имя сервиса в WSDL; если не указано, берется `Имя`.
- `КонтрольДоступа` на уровне сервиса задает право `Вызов`; если не указан,
  применяется default `РазрешеноАдминистраторам`.
- `Обработчики[].КонтрольДоступа` переопределяет доступ для отдельной
  операции.
- `Ошибки` на уровне сервиса и `Обработчики[].Ошибки` перечисляют типы
  исключений, которые войдут в WSDL faults.

Negative:

- Не добавляй `ШаблоныUrl`: это свойство `HttpСервис`, не SOAP-сервиса.
- Не создавай `.Wsdl.*` или `.Xsd.*` как входные файлы сервиса.
- Не указывай в `Ошибки` тип, который не является исключением.
- Не используй кириллицу в значении `Обработчики[].Метод`.

## UUID

Required:

- UUID получает сам объект `SoapСервис`.

Negative:

- `Обработчики[]`, структуры сообщений и исключения в `.xbsl` не получают
  YAML UUID.
- WSDL/XSD для сервиса не получают UUID, потому что не создаются как файлы
  проекта разработчика.

## Imports и visibility

Required:

- `ОбластьВидимости` задавай явно; default платформы: `ВПодсистеме`.
- `Импорт` добавляй только если сигнатуры операций, структуры сообщений или
  исключения ссылаются на типы из других пространств имен.

Negative:

- Не добавляй `Импорт` для встроенных типов `Строка`, `Число`, `Булево`,
  `Дата`, `ДатаВремя`, `Время`, `Месяц`, `Длительность`, `Байты`.
- Не поднимай `ОбластьВидимости` до `ВПроекте` без межподсистемной ссылки или
  явного требования пользователя.

## Companion artifacts

Required:

- `*.yaml` - описание SOAP-сервиса.
- `*.xbsl` - одноименный модуль SOAP-сервиса.

Optional:

- Нет required WSDL/XSD companion для сервиса: платформа формирует контракт из
  YAML и модуля.

Negative:

- Отсутствующий одноименный модуль является ошибкой, если в YAML есть
  `Обработчики[]`.
- Любой `Обработчики[].Метод` должен существовать в `<Имя>.xbsl`.

## Генерация

Required:

- Skill создает `<Имя>.yaml` и `<Имя>.xbsl`.
- Для каждой операции из `Обработчики[]` создай метод с тем же именем, которое
  указано в `Метод`.
- В модуле размещай структуры параметров/результатов и исключения, используемые
  сигнатурами операций.
- Для nullable сообщения используй только `Тип?`; произвольные union-типы в
  SOAP-сообщениях не генерируй.

Local conventions:

- Имена операций могут быть доменными, но имена методов обработчиков оставляй
  ASCII-friendly, например `GetOrder`, `CreateInvoice`, `CancelPayment`.
- Если пользователь не описал тело операции, создай skeleton метода без
  production-логики.

Negative:

- Не генерируй циклические структуры сообщений.
- Не генерируй коллекцию коллекций для SOAP-сообщения.
- Не создавай access policy шире запроса пользователя.

## Валидация

Required:

- `ВидЭлемента` равен `SoapСервис`.
- `ПространствоИменСервиса`, `КорневойUrl` и непустой `Обработчики[]`
  присутствуют.
- Все значения `Обработчики[].Метод` есть как методы в одноименном `.xbsl`.
- Все типы из `Ошибки` определены как исключения или являются доступными
  исключениями из импортированных пространств имен.
- Типы параметров и возвращаемых значений операций входят в поддержанный SOAP
  набор: scalar, структура, `Тип?`, `ЧитаемаяКоллекция<Тип>`.

Negative:

- `missing_service_module`.
- `handler_method_not_found`.
- `cyrillic_handler_name`.
- `soap_fault_is_not_exception`.
- `unsupported_soap_message_type`.
