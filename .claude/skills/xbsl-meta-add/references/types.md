# Типы данных реквизитов

| Тип | Пример использования | Доп. свойства |
|-----|---------------------|---------------|
| `Строка` | ФИО, телефон, адрес, текст | `МаксимальнаяДлина: 200` |
| `Число` | цена, количество, возраст | `ДлинаЦелойЧасти`, `ДлинаДробнойЧасти`, `МинимальноеЗначение` |
| `Булево` | активен, опубликован, флажок | — |
| `Дата` | дата рождения, дата приёма | — |
| `ДатаВремя` | дата и время события | — |
| `Момент` | временная метка с таймзоной | — |
| `ДвоичныйОбъект.Ссылка?` | фото, прикреплённый файл | — |
| `<Справочник>.Ссылка?` | ссылка на другой справочник | если объект из другой подсистемы — он должен иметь `ОбластьВидимости: ВПроекте` |
| `<Документ>.Ссылка?` | ссылка на документ | аналогично; если из другой подсистемы — объект должен иметь `ОбластьВидимости: ВПроекте` |
| `<Перечисление>?` | статус, вид, роль (nullable — по умолчанию) | `ИспользоватьВПолнотекстовомПоиске: Ложь` |
| `<Перечисление>` | статус с обязательным значением | требует `ЗначениеПоУмолчанию: <Перечисление>.<Элемент>` |
| `Пользователи.Ссылка?` | системный пользователь | — |
| `Массив<<Тип>.Ссылка>` | список ссылок одного типа | — |
| `Массив<<ТипА>.Ссылка\|<ТипБ>.Ссылка>` | список ссылок разных типов (union) | — |

## Параметры числовых полей

```yaml
Тип: Число
ДлинаЦелойЧасти: 10
ДлинаДробнойЧасти: 2
МинимальноеЗначение: 0
МаксимальноеЗначение: 9999999
ЗначениеПоУмолчанию: 0
```

## Параметры строковых полей

```yaml
Тип: Строка
МаксимальнаяДлина: 200      # для обычных строк
# или
Длина: 3                     # фиксированная длина (для кодов)
Многострочная: Истина        # для текстовых областей (описание, примечание)
НезаполненноеЗначение: ЗапретитьВсегда  # только для строкового пользовательского поля
```

## Флаги полей

- `НезаполненноеЗначение: Разрешить` или `ЗапретитьВсегда` — только для пользовательского поля с `Тип: Строка`; правило для системного `Наименование` см. в `Справочник.md`.
- `ИспользоватьВПолнотекстовомПоиске: Ложь` — для ссылок, перечислений, бинарных данных
- Поле с типом-перечислением **всегда** должно быть либо `<Перечисление>?` (nullable), либо иметь `ЗначениеПоУмолчанию`. Иначе проект не соберётся.
- `ЗаполнятьПриКопировании: Ложь` — для уникальных значений (пользователь, дата создания)

## Грамматика типов

Этот shared reference задаёт общий синтаксис типов для object references и
валидатора. Object references ссылаются на него через `shared_reference_paths`
из `object-coverage.json` и не копируют grammar локально.

```text
Type        := SimpleType Nullable?
            | ReferenceType Nullable?
            | ArrayType
            | UnionType
SimpleType  := Строка | Число | Булево | Дата | ДатаВремя | Момент | СекретПриложения
ReferenceType := <ИмяОбъекта>.Ссылка
ArrayType   := Массив< Type >
UnionType   := Type "|" Type
Nullable    := "?"
```

Правила:

- `?` применяется к конкретному типу и означает nullable-значение.
- `Массив<T>` хранит элементы типа `T`; вложенный `T` может быть ссылкой,
  nullable-ссылкой или union.
- Union использует символ `|` без изменения имён типов. В массиве union
  записывается внутри угловых скобок: `Массив<СправочникА.Ссылка|СправочникБ.Ссылка>`.
- `СекретПриложения` используется только там, где object reference содержит
  подтвержденное правило платформы о секрете; не подставляй его вместо обычной
  строки по догадке.

## Ограничения имён

Имена объектов, реквизитов, параметров, ресурсов и вложенных элементов
записываются в PascalCase или в документированном платформой виде. Имя не
должно содержать пробелы, точки, слеши, NUL-символы или пустые сегменты.

Ссылочные типы используют точное имя объекта: `<ИмяОбъекта>.Ссылка` или
`<ИмяОбъекта>.Ссылка?`. Если объект находится в другой подсистеме, правила
`Импорт` и `ОбластьВидимости` берутся из object reference и
`object-coverage.json`, а не из этого grammar-файла.
