# Спецификация: ВиртуальнаяТаблица

## Назначение

Факты платформы:

- `ВидЭлемента: ВиртуальнаяТаблица` описывает объект, данные которого задаются запросом из одноименного `.xbql`.
- Запрос должен быть непустым; параметры в YAML должны совпадать с `&`-параметрами запроса.

Соглашения генератора:

- Имя задавай PascalCase, существительное во множественном числе.
- Файл запроса размещай рядом с YAML и называй так же: `<Имя>.xbql`.

## YAML

Required:

```yaml
ВидЭлемента: ВиртуальнаяТаблица
Ид: <UUID>
Имя: <Имя>
ОбластьВидимости: ВПодсистеме
Параметры:
    -
        Имя: <ИмяПараметра>
        Тип: <Тип>
КлючевыеПоля:
    - <ИмяПоля>
```

Negative:

- Не добавляй `Параметры`, которых нет в `.xbql`.
- Не оставляй `&Параметр` в запросе без одноименного элемента `Параметры`.

## UUID

Required:

- UUID получает объект виртуальной таблицы.
- Параметры и ключевые поля в подтвержденной схеме не получают собственный UUID.

Negative:

- Не добавляй UUID параметрам запроса.

## Imports и visibility

Required:

- `ОбластьВидимости` выбирай явно: `ВПодсистеме` для локального использования, `ВПроекте` при межподсистемном чтении.
- Если запрос обращается к объектам другой подсистемы, добавляй нужный `Импорт` по общему workflow skill.

Negative:

- Не объявляй импорт, если запрос использует только объекты текущей подсистемы.

## Companion artifacts

Required:

- `*.yaml` - описание объекта.
- `*.xbql` - обязательный одноименный непустой запрос.

Negative:

- Отсутствующий, пустой или иначе названный `.xbql` не является валидным комплектом.

## Генерация

Required:

- Skill создает пару `<Имя>.yaml` и `<Имя>.xbql`.
- Перед записью сверяет базовые имена файлов и множества параметров.

Negative:

- Повторный запуск не должен создавать второй запрос с другим базовым именем.

## Валидация

Required:

- `basename(yaml) == basename(xbql)`.
- `set(Параметры[].Имя) == set(&ПараметрыВЗапросе)`.
- `.xbql` после `strip()` не пустой.

Negative:

- `empty_query`, `missing_query`, `parameter_mismatch`.
