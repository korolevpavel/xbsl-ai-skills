# Спецификация: КлючДоступа

## Дефолты

- **Имя** — PascalCase, описывает роль/контекст (`КлючДоступаМенеджера`, `КлючДоступаАдминистратора`, `КлючДоступаСотрудника`)
- **Видимость** — `ВПроекте` (ключи доступа обычно используются в нескольких местах)

## UUID

Нужен: 1 (объект) + по 1 на каждый параметр, определённый разработчиком.
Системный параметр `Владелец` UUID не требует.

## Структура YAML

### Минимальная (без параметров):

```yaml
ВидЭлемента: КлючДоступа
Ид: <UUID>
Имя: <ИмяКлюча>
ОбластьВидимости: ВПроекте
```

### С параметрами:

```yaml
ВидЭлемента: КлючДоступа
Ид: <UUID>
Имя: <ИмяКлюча>
ОбластьВидимости: ВПроекте
Импорт:                          # необязательно
    - <ИмяПодсистемы>
Параметры:
    -
      Имя: Владелец
      Тип: Сотрудники.Ссылка?    # кому принадлежит доступ
    - Ид: <UUID>
      Имя: УровеньДоступа
      Тип: УровниДоступа          # уровень или вид доступа
```

## Правила

- Ключ доступа — именованный маркер, по которому система определяет права
- `Параметры` — уточняют контекст доступа (чей доступ, к какому объекту, с какой ролью)
- Ключи без параметров — для глобальных ролей (`КлючДоступаАдминистратора`)
- Ключи с параметрами — для доступа к конкретным объектам (`КлючДоступаМенеджера` с `Владелец`)
- Уточнение: системный параметр `Владелец` не содержит `Ид`; указывайте только
  `Имя: Владелец` и `Тип`.
- Каждый пользовательский параметр содержит `Ид`, `Имя` и `Тип`.

## Разрешения и проверка прав

Доступ к объектам сущности задавайте через обработчики расчёта
`РазрешениеДоступа` (например, `ВычислитьРазрешенияДоступа` и, при расчёте для
каждого объекта, `ВычислитьРазрешенияДоступаДляОбъектов`): обработчик возвращает
разрешения, связанные с экземплярами ключей доступа.

Если требуется проверить общее право, используйте только документированные методы
`КонтрольДоступа.ЕстьПраво(...)` или `КонтрольДоступа.ПроверитьПраво(...)` —
выбирайте их по требованию, а не для ручной проверки экземпляра ключа доступа.
