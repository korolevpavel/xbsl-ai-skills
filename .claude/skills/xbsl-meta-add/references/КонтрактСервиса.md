# Спецификация: КонтрактСервиса

## Назначение

Platform facts:

- `ВидЭлемента: КонтрактСервиса` описывает контракт сервисного API.
- Свойство `Обязательный: Истина` требует хотя бы одну реализацию контракта.
- Свойство `Множественный` выбирает порождаемый API: `ПолучитьСервис()` для
  единственной реализации и `ПолучитьСервисы()` для множественной.
- Одноименный модуль `<Имя>.xbsl` содержит абстрактные методы и типы контракта.

Local conventions:

- Если пользователь просит реализацию контракта, создавай отдельный
  `ОбщийМодуль`, реализующий контракт через `НастройкиТипа.Контракты`.
- Не смешивай абстрактный модуль контракта и модуль реализации.

## YAML

Required:

```yaml
ВидЭлемента: КонтрактСервиса
Ид: <UUID>
Имя: <ИмяКонтракта>
ОбластьВидимости: ВПроекте
Окружение: КлиентИСервер
Обязательный: Истина
Множественный: Ложь
```

Optional:

- `Обязательный` имеет default `Ложь`; optional-контракт может не иметь
  реализации.
- `Множественный` имеет default `Истина`.
- `НастройкиТипа.Контракты` задаёт базовые сервисные контракты.

Negative:

- Контракт с `Обязательный: Истина` требует отдельной реализации перед
  запуском проекта.
- Optional-контракт с опущенным `Обязательный` или `Обязательный: Ложь`
  не должен отклоняться только из-за отсутствия реализации.

## UUID

Required:

- UUID получает сам `КонтрактСервиса`.

Negative:

- Методы и типы внутри одноименного `.xbsl` не получают YAML UUID.

## Imports и visibility

Required:

- `ОбластьВидимости` задавай явно.
- `Импорт` указывай только при ссылках на объекты другой подсистемы.
- Модуль контракта использует обычный XBSL `импорт`, если его методы ссылаются
  на типы другой подсистемы.

Negative:

- Не поднимай visibility реализации, если контракт не используется за пределами
  подсистемы.

## Companion artifacts

Required:

- `*.yaml` - описание контракта сервиса.
- `*.xbsl` - одноименный модуль контракта с абстрактными методами.

Negative:

- Отсутствующий модуль контракта является ошибкой.
- Реализация обязательного контракта должна быть отдельным общим модулем, а не
  вторым содержимым файла контракта.

## Генерация

Required:

- Skill создает `<Имя>.yaml` и `<Имя>.xbsl`.
- Для пользовательского проекта skill не создает production-реализацию сервиса,
  если пользователь не просил её явно.

Local conventions:

- Если пользователь просит готовую реализацию, добавляй отдельный
  `ОбщийМодуль`, чтобы не смешивать абстрактную сигнатуру и реализацию.

Negative:

- Повторный запуск не должен заменять optional-контракт required-вариантом.

## Валидация

Required:

- Для `Обязательный: Истина` проверяй одноименный `.xbsl`; реализацию добавляй
  отдельным `ОбщийМодуль` с `НастройкиТипа.Контракты`, если пользователь просит
  готовый runnable-комплект.
- Сигнатуры абстрактных методов и методов с `@Реализация` совместимы.

Negative:

- `missing_contract_module`.
- `missing_required_implementation`.
- `incompatible_implementation_signature`.
