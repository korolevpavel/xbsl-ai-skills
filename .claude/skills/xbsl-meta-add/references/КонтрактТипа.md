# Спецификация: КонтрактТипа

## Назначение

Platform facts:

- `ВидЭлемента: КонтрактТипа` описывает абстрактный тип встроенного языка.
- `Свойства[]` задают свойства контракта типа.
- `НастройкиТипа.Контракты` у контракта задает базовые контракты типа.
- Модуль `<Имя>.xbsl` может объявлять абстрактные методы, но для минимального
  YAML-only контракта с одними свойствами не является обязательным.

Local conventions:

- Реализующий тип не является обязательным companion обычной генерации.

## YAML

Required:

```yaml
ВидЭлемента: КонтрактТипа
Ид: <UUID>
Имя: <ИмяКонтракта>
ОбластьВидимости: ВПодсистеме
Окружение: КлиентИСервер
Свойства:
    -
        Имя: <ИмяСвойства>
        Тип: <Тип>
        ТолькоЧтение: Ложь
```

Optional:

- `НастройкиТипа.Контракты` указывает базовые контракты типа.
- `ТолькоЧтение: Истина` допускает source-backed сужение ссылочного или
  составного типа реализации.

Negative:

- `НастройкиТипа` внутри `КонтрактТипа` не является `НастройкиТипов`
  реализующего объектного вида.
- Read-write свойство реализации не может менять тип.

## UUID

Required:

- UUID получает сам `КонтрактТипа`.

Negative:

- Элементы `Свойства[]` в подтвержденной схеме не получают собственного UUID.

## Imports и visibility

Required:

- `ОбластьВидимости` и `Окружение` задавай явно.
- `Импорт` нужен только для ссылок на типы другой подсистемы.

Negative:

- Не добавляй import для локальных типов.

## Companion artifacts

Required:

- `*.yaml` - описание контракта типа.

Negative:

- `.xbsl` не является обязательным companion, если контракт содержит только
  YAML-свойства.
- Реализующий тип не создается без явного запроса пользователя.

## Генерация

Required:

- Skill создает `<Имя>.yaml`.
- При запросе абстрактных методов пользователь отдельно просит модуль
  `<Имя>.xbsl`.

Local conventions:

- Если пользователь просит пример реализации, добавляй отдельную `Структура`
  или другой тип, реализующий контракт через `НастройкиТипа.Контракты`.

Negative:

- Не подменяй контракт типа обычной `Структура`.

## Валидация

Required:

- Read-write свойство реализации точно совпадает с типом контракта.
- Read-only сужение допускается только для случаев, подтвержденных источником.

Negative:

- `incompatible_mutable_property`.
- `invalid_readonly_narrowing`.
