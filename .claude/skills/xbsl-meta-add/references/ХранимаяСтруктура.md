# Спецификация: ХранимаяСтруктура

## Назначение

Факты платформы:

- `ВидЭлемента: ХранимаяСтруктура` описывает структуру данных с набором полей.
- Каждое поле имеет имя и тип, пригодный для хранения.

Соглашения генератора:

- Имя задавай PascalCase по смыслу структуры.
- Типы сверяй по `references/types.md` и ограничениям источника.

## Версия и источники

| Claim | Источник | Проверено | Что подтверждает |
| --- | --- | --- | --- |
| YAML-схема хранимой структуры | `topics/latest/storable-structure-properties` | 2026-07-28 | `ВидЭлемента`, `Поля`, свойства поля |

## YAML

Required:

```yaml
ВидЭлемента: ХранимаяСтруктура
Ид: <UUID>
Имя: <Имя>
ОбластьВидимости: ВПодсистеме
Поля:
    -
        Ид: <UUID>
        Имя: <ИмяПоля>
        Тип: <Тип>
```

Negative:

- Не смешивай контракт с обычным `ВидЭлемента: Структура`.
- Не используй непередаваемые или нехранимые runtime-типы как поля.

## UUID

Required:

- UUID получает объект хранимой структуры.
- UUID получает каждое поле `Поля[]`.

Negative:

- Не добавляй UUID вложенным значениям внутри типа поля.

## Imports и visibility

Required:

- `ОбластьВидимости` задавай явно.
- Ссылочные типы полей проверяй через общий workflow межподсистемных ссылок.

Negative:

- Не используй ссылочный тип, если объект-источник не найден.

## Companion artifacts

Required:

- `*.yaml` - описание объекта.

Negative:

- XBSL/XBQL companion не является обязательным.

## Генерация

Required:

- Skill создает YAML с полями.
- Для каждого поля генерируется UUID и проверяется тип.

Negative:

- Не создавай модуль для структуры без прямого запроса пользователя.

## Валидация

Required:

- `Поля` непустой список.
- Каждый элемент `Поля[]` содержит `Ид`, `Имя`, `Тип`.
- Тип поля должен быть допустимым хранимым типом.

Negative:

- `non_storable_type`.
