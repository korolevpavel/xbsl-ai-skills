# xbsl-yandex-maps

Скилл добавляет интерактивную Яндекс.Карту в форму объекта 1С:Элемент.
Нативная поддержка Яндекс.Карт в платформе не реализована — скилл использует внешнюю библиотеку.

**Дефолтная библиотека:** https://github.com/korolevpavel/xbsl-yandex-maps

---

## Шаг 0 — Извлечь параметры из запроса

Из запроса пользователя определить:

- **ИмяОбъекта** — имя справочника или документа (например, `Склады`)
- **ТипФормы** — по умолчанию `ФормаОбъекта`
- **ПолеАдреса** — поле объекта с адресом (если указано явно)
- **ВысотаКарты** — высота блока карты в px (по умолчанию `400`)

## Шаг 1 — Предложить варианты пользователю

Сообщить:

> **Нативная поддержка Яндекс.Карт в 1С:Элемент пока не реализована.**
>
> Доступны два варианта:
> 1. **Подключить через внешнюю библиотеку** — интерактивная карта через библиотеку ЯндексКарты (рекомендуется)
> 2. **Ничего не делать** — вернуться к этому позже, когда появится нативная поддержка

Спросить пользователя о выборе.

**Если выбран вариант 2** → завершить:
> "Когда платформа добавит нативную поддержку Яндекс.Карт, вы сможете повторно обратиться к этому скиллу."

## Шаг 2 — Найти объект и проверить наличие библиотеки

Запустить разведку для нахождения объекта:

```bash
python3 .claude/skills/xbsl-explore/scripts/explore.py \
    --type Справочник --name {ИмяОбъекта} --root .
```

Если тип объекта не Справочник — подобрать нужный (Документ и т.д.).

Из результата извлечь `project_yaml_path` (путь к `Проект.yaml`). Прочитать его.

Проверить наличие библиотеки ЯндексКарты в разделе `Библиотеки`:
```yaml
Библиотеки:
  - Имя: ЯндексКарты
    ...
```

- Если библиотека **уже подключена** → перейти к Шагу 3.5.
- Если **не подключена** → перейти к Шагу 3.

## Шаг 3 — Подключить библиотеку через xbsl-lib-connect

Сообщить пользователю и запросить подтверждение:

> Библиотека ЯндексКарты не найдена в `Проект.yaml`. Нужно её подключить.
> Подключить сейчас? (источник по умолчанию: https://github.com/korolevpavel/xbsl-yandex-maps)
> Введите `да` / URL / путь к .xlib — или `нет` чтобы отменить.

**Если пользователь ответил `нет`** → завершить:
> "Без библиотеки добавить карту не получится. Вы сможете вернуться к этому позже."

**Если пользователь подтвердил** (ввёл `да`, URL или путь):
- Использовать введённое значение как источник (если `да` или Enter — дефолтный URL)
- Вызвать скилл подключения:
```
Skill("xbsl-lib-connect")
```

Следовать всем шагам xbsl-lib-connect.

Если подключение завершилось с ошибкой → сообщить об ошибке и остановиться.

После успешного подключения прочитать обновлённый `Проект.yaml`, извлечь
`LIB_VENDOR` и `LIB_NAME` из добавленной записи в `Библиотеки`.

## Шаг 3.5 — Предложить вывести настройки API-ключа в интерфейс

Для работы карты обязательно нужен API-ключ Яндекс. Его заполняют в объекте
`НастройкиYandexMaps` из библиотеки. Чтобы этот объект был доступен в интерфейсе,
его нужно явно добавить в навигацию приложения.

**Важно:** `ВключатьВАвтоИнтерфейс: Истина` на библиотечных объектах **не работает**
в приложениях с ручной навигацией (а большинство приложений именно такие).
Нужно добавить команду `=НастройкиYandexMaps.ОткрытьФорму` в навигационный файл явно.

Спросить пользователя:

> Для работы карты нужен API-ключ Яндекс. Добавить пункт "Настройки Yandex Maps"
> в навигацию приложения?
> - `да` — найду файл навигации и покажу что именно изменю, затем спрошу подтверждение
> - `нет` — сделаете это вручную позже

**Если пользователь ответил `нет`** → продолжить к Шагу 4, в Шаге 9 напомнить
о необходимости добавить вручную.

**Если пользователь согласился:**

### 1. Найти навигационный файл

Искать в проекте файл с `Тип: СтандартноеКлиентскоеПриложениеСРазделами` —
это корневой файл навигации (обычно `Приложение.yaml`):

```bash
grep -rl "СтандартноеКлиентскоеПриложениеСРазделами" {project_dir} --include="*.yaml"
```

- Если найден **один файл** → использовать его.
- Если найдено **несколько** → показать список, спросить пользователя.
- Если **не найден** → сообщить:
  > "Не удалось найти файл навигации приложения. Добавьте вручную команду
  > `=НастройкиYandexMaps.ОткрытьФорму` в нужную группу навигации."
  И перейти к Шагу 4.

### 2. Определить целевую группу

Прочитать найденный файл. Показать пользователю список групп навигации
(`ГруппаКомандногоИнтерфейса`) с их `Представление`.

Спросить:

> Найден файл навигации: `{путь к файлу}`
> Группы навигации: {список групп}
> В какую группу добавить "Настройки Yandex Maps"?
> (по умолчанию: `Основное`, если есть)

### 3. Предупредить и получить подтверждение

Показать точное изменение которое будет внесено:

> **Планирую добавить в файл `{путь}`** в группу `{группа}`:
> ```
> - =НастройкиYandexMaps.ОткрытьФорму
> ```
> Это изменит навигацию приложения. Продолжить?

**Только после подтверждения** — добавить строку `- =НастройкиYandexMaps.ОткрытьФорму`
в конец списка `Элементы` выбранной группы.

Сообщить: «Готово. После деплоя раздел "Настройки Yandex Maps" появится в навигации.»

## Шаг 7 — Добавить компонент карты в форму

Загрузить шаблоны из `references/карта-форма-объекта.md`.

Библиотека предоставляет готовый компонент **`КартаЯндекса`** — `КонтейнерHtml` вручную
не нужен. Компонент принимает список меток `Массив<МеткаКарты>` с координатами.

### Проверить наличие полей координат

Если у объекта нет полей `ЯндексКартаШирота: Число?` и `ЯндексКартаДолгота: Число?` — спросить пользователя:

> У объекта `{ИмяОбъекта}` нет реквизитов для координат (`ЯндексКартаШирота`, `ЯндексКартаДолгота`).
> Карта использует их для отображения метки на карте.
> Добавить реквизиты `ЯндексКартаШирота: Число?` и `ЯндексКартаДолгота: Число?`?

**Если пользователь отказался** — продолжить без полей координат: добавить только компонент
`КартаЯндекса` без привязки к координатам. В `.xbsl` метод `ПолучитьМетки()` будет
возвращать пустой массив.

**Если согласился** — добавить поля в `.yaml` объекта. UUID генерировать через `xbsl-uuid`.

### Если ФормаОбъекта уже существует

Прочитать файл `{object_path}/ФормаОбъекта.yaml`. Добавить:

1. В начало файла (до `Наследует:`):
```yaml
Импорт:
    - korolevpavel::YandexMaps::Основное
Свойства:
    -
        Имя: МеткиКарты
        Тип: Массив<МеткаКарты>
```

2. В `Содержимое` формы — поля координат рядом с другими реквизитами:
```yaml
-
    Тип: ПолеВвода<Число?>
    Имя: ЯндексКартаШирота
    Значение: =Объект.ЯндексКартаШирота
    ПриИзменении: КоординатыПриИзменении
-
    Тип: ПолеВвода<Число?>
    Имя: ЯндексКартаДолгота
    Значение: =Объект.ЯндексКартаДолгота
    ПриИзменении: КоординатыПриИзменении
```

3. В `Содержимое` формы — компонент карты после полей (полная ширина):
```yaml
-
    Тип: КартаЯндекса
    Имя: Карта
    Метки: =МеткиКарты
    АвтоПодобратьГраницы: Истина
    КластеризоватьМетки: Истина
    РастягиватьПоГоризонтали: Истина
    Высота: {ВысотаКарты}
    ШиринаВКолонках: Двойная
```

### Если ФормаОбъекта НЕ существует

Создать `{object_path}/ФормаОбъекта.yaml` с минимальной структурой, включающей
поля координат и `КартаЯндекса`. UUID генерировать через `xbsl-uuid`. Образец из
`references/карта-форма-объекта.md`.

### Обновить Подсистема.yaml

Найти `Подсистема.yaml` подсистемы, в которой находится объект. Добавить в раздел
`Использование` ссылку на библиотеку (Секция 4 reference-файла):

```yaml
Использование:
    - korolevpavel::YandexMaps::Основное
```

Без этого платформа при деплое выдаст ошибку: *"Подсистема не указана в качестве используемой"*.

## Шаг 8 — Создать/дополнить .xbsl файл формы

**Если `.xbsl` НЕ существует** — создать с содержимым из reference-файла (Секция 3).

**Если файл уже существует** — прочитать и добавить:
- Строку `импорт korolevpavel::YandexMaps::Основное` в начало
- Метод `ПослеСоздания` (если нет) или вставить `МеткиКарты = ПолучитьМетки()` в его начало
- Метод `ПолучитьМетки(): Массив<МеткаКарты>` — создаёт метку из полей объекта
- Метод `КоординатыПриИзменении` — вызывает `ПолучитьМетки()` при изменении полей
