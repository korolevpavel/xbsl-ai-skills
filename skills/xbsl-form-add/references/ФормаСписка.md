# Спецификация: ФормаСписка

## Структура YAML

> `<ns>` — значение `namespace` из скрипта (`vendor::project::subsystem`)

```yaml
ВидЭлемента: КомпонентИнтерфейса
Ид: <UUID>
Имя: <ИмяОбъекта>ФормаСписка
ОбластьВидимости: ВПодсистеме
Наследует:
    Тип: ФормаСписка
    ВключатьВАвтоИнтерфейс: Ложь
    Заголовок: <Заголовок>
    ДополнительныеКоманды:
        Тип: ФрагментКомандногоИнтерфейса
        Элементы:
            - =Обновить
    КомандыСоздания: =Компоненты.ОсновнаяТаблица.ДобавитьСтроку
    КомпонентТаблицы: =Компоненты.ОсновнаяТаблица
    Содержимое:
        Тип: ПроизвольныйШаблонФормы
        Содержимое:
            Тип: Таблица<ДинамическийСписок<<ns>::<ИмяОбъекта>ФормаСписка.ДанныеСтрокиСписка>>
            Имя: ОсновнаяТаблица
            Источник: =Список
            Колонки:
                -
                    Тип: СтандартнаяКолонкаТаблицы<СтрокаДинамическогоСписка<<ns>::<ИмяОбъекта>ФормаСписка.ДанныеСтрокиСписка>>
                    Имя: <Поле1>
                    Значение: =ДанныеСтроки.Данные.<Поле1>
                -
                    Тип: СтандартнаяКолонкаТаблицы<СтрокаДинамическогоСписка<<ns>::<ИмяОбъекта>ФормаСписка.ДанныеСтрокиСписка>>
                    Имя: <Поле2>
                    Значение: =ДанныеСтроки.Данные.<Поле2>
            КомандыСтроки:
                Тип: ФрагментКомандногоИнтерфейса<КомандаСПараметром<СтрокаДинамическогоСписка<<ns>::<ИмяОбъекта>ФормаСписка.ДанныеСтрокиСписка>>>
                Элементы:
                    - =Компоненты.ОсновнаяТаблица.СоздатьКопию

    -
        Имя: Список
        Тип: ДинамическийСписок<<ns>::<ИмяОбъекта>ФормаСписка.ДанныеСтрокиСписка>
        ЗначениеПоУмолчанию:
            ИмяТипаДанныхСтроки: ДанныеСтрокиСписка
            ОсновнаяТаблица:
                Таблица: <ИмяОбъекта>
            Поля:
                -
                    Тип: ПолеДинамическогоСписка

                    Тип: ПолеДинамическогоСписка
                    Выражение: <Поле2>
```

## Правила

- `ВключатьВАвтоИнтерфейс: Ложь` — обязательно всегда
- `<ns>` — полный namespace из скрипта (`namespace`), например `korolevpavel::cc_1c_xbsl_test::Основное`
- `КомандыСоздания: =Компоненты.ОсновнаяТаблица.ДобавитьСтроку` — всегда именно так
- `Источник: =Список` — таблица ссылается на свойство `Список`, определённое в `Свойства`
- Колонки: `Значение: =ДанныеСтроки.Данные.<Поле>` — так привязываются данные строки
- `Имя` колонки — произвольное, обычно совпадает с именем поля
- Поля в `Свойства.ЗначениеПоУмолчанию.Поля` — должны совпадать с полями в колонках

### Выбор колонок

Добавляй **все поля объекта** как колонки. Для Справочника первая колонка — всегда `Наименование`, затем остальные поля в порядке из YAML объекта.

## Сортировка

```yaml
            ЗначениеПоУмолчанию:
                ...
                Сортировка:
                    -
                        Поле: <ПолеСортировки>
                        НаправлениеСортировки: ПоУбыванию   # или ПоВозрастанию
```

Документы обычно сортируются по `Дата` возрастанию. Справочники — по `Наименование` возрастанию.

## Колонка со статусом (перечисление с цветом)

```yaml
                -
                    Тип: СтандартнаяКолонкаТаблицы<СтрокаДинамическогоСписка<<ns>::<ИмяОбъекта>ФормаСписка.ДанныеСтрокиСписка>>
                    Имя: Статус
                    Значение: =ДанныеСтроки.Данные.Статус
                    Вид: Значок
                    Цвет: =ДанныеСтроки.Данные.Статус.ПолучитьЦвет()
```

## Иерархический список с деревом

Используется когда `form_info.py` вернул `is_hierarchical: true`. Выбирай паттерн по `hierarchy_kind`: в target 10.0 отсутствие `Иерархия.Вид` означает `ИерархияГруппИЭлементов`.

### Паттерн А — иерархия элементов (`Иерархия.Вид: ИерархияЭлементов`)

В таблице добавить `НачальныйУровеньРазворачивания: -1` (дерево разворачивается полностью).
В `Свойства → Список → ЗначениеПоУмолчанию` добавить `ИспользуемаяИерархия`.
В `Поля` включить `Родитель` (системный реквизит — не в YAML объекта, но в форме нужен).

> ⚠️ **Важно**: для иерархического списка `ДинамическийСписок` требует **два одинаковых типовых параметра** `<T, T>` (первый — тип данных строки, второй — тип данных узла дерева). Одиночный `<T>` вызывает ошибку платформы `DynamicListRowData<never>`.

```yaml
Наследует:
    Тип: ФормаСписка
    ...
    Содержимое:
        Тип: ПроизвольныйШаблонФормы
        Содержимое:
            Тип: Таблица<ДинамическийСписок<<ns>::<ИмяОбъекта>ФормаСписка.ДанныеСтрокиСписка, <ns>::<ИмяОбъекта>ФормаСписка.ДанныеСтрокиСписка>>
            Имя: ОсновнаяТаблица
            Источник: =Список
            НачальныйУровеньРазворачивания: -1
            Колонки:
                -
                    Тип: СтандартнаяКолонкаТаблицы<СтрокаДинамическогоСписка<<ns>::<ИмяОбъекта>ФормаСписка.ДанныеСтрокиСписка>>
                    Имя: Наименование
                    Значение: =ДанныеСтроки.Данные.Наименование
                # ...остальные колонки
Свойства:
    -
        Имя: Список
        Тип: ДинамическийСписок<<ns>::<ИмяОбъекта>ФормаСписка.ДанныеСтрокиСписка, <ns>::<ИмяОбъекта>ФормаСписка.ДанныеСтрокиСписка>
        ЗначениеПоУмолчанию:
            ИмяТипаДанныхСтроки: ДанныеСтрокиСписка
            ИспользуемаяИерархия:
                Тип: Строка
                Значение: Иерархия    # таблица иерархии элементов
            ОсновнаяТаблица:
                Таблица: <ИмяОбъекта>
            Поля:
                -
                    Тип: ПолеДинамическогоСписка
                    Выражение: Родитель
                -
                    Тип: ПолеДинамическогоСписка
                    Выражение: Наименование
                # ...остальные поля
```

### Группы и элементы (target 10.0+)

Исходный справочник должен иметь `Иерархический: Истина` и `Иерархия.Вид: ИерархияГруппИЭлементов`. Платформа порождает `Товары.Группы` автоматически. Дерево списка строится по `Товары.ИерархияГруппИЭлементов`; `ИспользуемаяИерархия` задаёт имя этой иерархии строкой. Первый параметр `ДинамическийСписок` описывает строки товаров, второй — строки узлов дерева; при схеме с общими отображаемыми полями допускается тот же сгенерированный тип строки, как у автоматической формы списка. Не создавай второй объект метаданных ради групп.

```yaml
Наследует:
    Тип: ФормаСписка
    КомпонентТаблицы: =Компоненты.ОсновнаяТаблица
    Содержимое:
        Тип: ПроизвольныйШаблонФормы
        Содержимое:
            Тип: Таблица<ДинамическийСписок<<ns>::ТоварыФормаСписка.ДанныеСтрокиСписка, <ns>::ТоварыФормаСписка.ДанныеСтрокиСписка>>
            Имя: ОсновнаяТаблица
            Источник: =Список
            НачальныйУровеньРазворачивания: -1
            Колонки:
                - Тип: СтандартнаяКолонкаТаблицы<СтрокаДинамическогоСписка<<ns>::ТоварыФормаСписка.ДанныеСтрокиСписка>>
                  Имя: Наименование
                  Значение: =ДанныеСтроки.Данные.Наименование
Свойства:
    - Имя: Список
      Тип: ДинамическийСписок<<ns>::ТоварыФормаСписка.ДанныеСтрокиСписка, <ns>::ТоварыФормаСписка.ДанныеСтрокиСписка>
      ЗначениеПоУмолчанию:
          ИмяТипаДанныхСтроки: ДанныеСтрокиСписка
          ИспользуемаяИерархия:
              Тип: Строка
              Значение: ИерархияГруппИЭлементов
          ОсновнаяТаблица:
              Таблица: Товары
          Поля:
              - Тип: ПолеДинамическогоСписка
                Выражение: Наименование
              - Тип: ПолеДинамическогоСписка
                Выражение: Родитель
```

В `Товары` поле `Родитель` и ключ узла группы имеют тип `Товары.Группы.Ссылка?`, а ключ строки элемента — `Товары.Ссылка`; не приводи оба к одному ссылочному типу. При навигации по группе дерево раскрывает её дочерние группы и элементы. Открытие строки элемента использует форму объекта `Товары`; для отдельного открытия группы нужна форма группы, порождённая платформой. Команды для отдельной формы списка групп по умолчанию отсутствуют в автоинтерфейсе; их можно включить через `Иерархия.СправочникГрупп.ВключатьВАвтоИнтерфейс` или открыть форму явно. [Иерархический справочник](https://1cmycloud.com/console/help/element/10.0/docs/topics/hierarchical-catalog/) · [типы ключей](https://1cmycloud.com/console/help/element/10.0/docs/stdlib/element/xbql/Std/CatalogNameWithGroups/CatalogNameWithGroups.HierarchyOfGroupsAndElements_ru/) · [динамический список](https://1cmycloud.com/console/help/element/10.0/docs/stdlib/element/xbsl/Std/Interface/DataSources/DynamicList/DynamicList_ru/).

### Паттерн Б — дополнительные иерархии (`additional_hierarchies` не пуст)

`ИспользуемаяИерархия.Значение` — имя из `ДополнительныеИерархии` (например `"Проект"`).
Поле `Родитель` в `Поля` не добавляется — родительская связь через обычный реквизит-ссылку.

```yaml
ЗначениеПоУмолчанию:
    ИспользуемаяИерархия:
        Тип: Строка
        Значение: <ИмяИзДополнительныеИерархии>    # например "Проект"
    ОсновнаяТаблица:
        Таблица: <ИмяОбъекта>
    Поля:
        -
            Тип: ПолеДинамическогоСписка
            Выражение: Наименование
        -
            Тип: ПолеДинамическогоСписка
            Выражение: <ПолеРодителя>    # само поле-ссылка, например Проект
        # ...остальные поля
```

## Действия над отмеченными строками

Для целевой платформы 10.0 используется
[`КомандыОтмеченныхСтрок`](https://1cmycloud.com/console/help/element/10.0/docs/stdlib/element/xbsl/Std/Interface/Lists/List_ru/).
Если целевая версия платформы ниже 10.0, сверяй имя свойства с её
документацией. Каждой отдельной команде внутри фрагмента задавай уникальное `Имя`;
ссылки на готовые команды вида `- =Обновить` остаются ссылками.

```yaml
            ИспользоватьОтметкиСтрок: Истина
            КомандыОтмеченныхСтрок:
                Тип: ФрагментКомандногоИнтерфейса<КомандаСПараметром<Массив<<ИмяОбъекта>.Ссылка>>>
                Элементы:
                    -
                        Тип: КомандаСПараметром<Массив<<ИмяОбъекта>.Ссылка>>
                        Имя: <ИмяКоманды>
                        Представление: <ТекстКоманды>
                        Изображение: <Иконка>.svg
                        Обработчик: <ИмяОбработчика>
```
