# Общий контракт object reference

## Назначение

Каждый object reference описывает ровно один функциональный `ВидЭлемента` и
ссылается на общий registry `skills/xbsl-meta-add/object-coverage.json`.
Reference фиксирует только подтвержденные свойства платформы и отдельно
называет правила навыка.

Если раздел к объекту не относится, не удаляй его: пиши краткую причину,
основанную на контракте объекта.

## Версия

Укажи минимальную версию платформы для объекта или feature-delta. Не включай
служебные таблицы, URL, даты проверки и локальные evidence-файлы в public
reference.

## YAML

Опиши минимальный YAML и затем опциональные свойства. Для каждого поля укажи
обязательность, тип, default, enum и cardinality только когда это закреплено
текущим контрактом объекта.

## UUID

Зафиксируй UUID-формулу объекта: какие элементы получают UUID, какие системные
элементы UUID не получают и какие вложенные коллекции требуют собственных UUID.

## Imports и visibility

Опиши `Импорт`, `ОбластьВидимости` и взаимные ограничения ссылок между
подсистемами. Если контракт объекта не фиксирует default или optionality, не
выдавай локальную практику за правило платформы.

## Companion artifacts

Перечисли обязательные и необязательные companion-файлы: `.xbsl`, `.xbql`,
WSDL, XSD, схемы процессов и другие ресурсы. Для отсутствующего companion
укажи краткую причину из контракта объекта.

## Генерация

Опиши, какие артефакты skill создаёт, какие оставляет разработчику и как
обрабатывает повторный запуск. В этом разделе допустимы правила генерации
навыка, но они не становятся фактами платформы.

## Валидация

Опиши позитивные и negative contract-сценарии: обязательные поля, согласованность
имён, ссылки на companion-файлы, типы, обработчики и ожидаемые diagnostics.
