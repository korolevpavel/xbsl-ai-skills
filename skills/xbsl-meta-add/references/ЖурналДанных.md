# Спецификация: ЖурналДанных

## Назначение

Факты платформы:

- `ЖурналДанных` объединяет записи справочников и документов из непустого `Состав`.
- У журнала нет собственных прав: права на чтение и RLS наследуются от элементов `Состав`.
- `Колонки` отображают реквизиты разных источников в одном поле таблицы.

Соглашения генератора:

- Перед созданием проверь существование каждого источника и реквизита в проекте.
- Для одноимённых элементов в разных пространствах имён уточни источник и импорт.

## Версия

- Минимальная версия платформы: 10.0+.

## YAML

Required:

```yaml
ВидЭлемента: ЖурналДанных
Ид: <UUID>
Имя: <ИмяЖурнала>
ОбластьВидимости: ВПодсистеме
Состав:
  - Элемент: <ИмяСправочника>
  - Элемент: <ИмяДокумента>
Колонки:
  - Ид: <UUID>
    Имя: <ИмяКолонки>
    Реквизиты:
      - <ИмяСправочника>.<ИмяРеквизита>
      - <ИмяДокумента>.<ИмяРеквизита>
```

`Колонки` необязательны, если достаточно стандартных полей. Если колонка
добавлена, её `Реквизиты` не могут быть пустыми. Элементы состава могут быть
только `Справочник` или `Документ`.

Negative:

- Не создавай `КонтрольДоступа` в журнале.
- Не добавляй пустой `Состав` или реквизит источника, отсутствующего в `Состав`.

## UUID

Required:

- UUID получает журнал и каждая запись `Колонки`.

Negative:

- Не добавляй UUID записям `Состав` и строкам `Реквизиты`.

## Imports и visibility

Required:

- Для источников другой подсистемы проверь `ОбластьВидимости` и добавь `Импорт` по общему workflow.
- `ВПодсистеме` подходит для журнала, используемого только в своей подсистеме.

Negative:

- Не считай наличие элемента в файловом дереве доказательством его доступности через пространство имён.

## Companion artifacts

Required:

- `<ИмяЖурнала>.yaml` — единственный обязательный файл.

Negative:

- Модуль журнала и форму списка создавай только при необходимости.

## Генерация

Required:

- Собери `Состав` из существующих справочников/документов. Для каждой колонки
  проверь `Реквизиты` вида `<Источник>.<Реквизит>`; источник должен быть в `Состав`.
- Подсчитай UUID: 1 на журнал и по 1 на колонку.
- Для смешанного состава не рассчитывай на стандартные поля `Дата`, `Номер`,
  `Наименование`, `Код`; создай явную колонку, если она нужна.

Negative:

- Не создавай отдельные права на журнал.

## Валидация

Required:

- Проверь непустой `Состав`, виды и разрешение ссылок источников.
- Проверь UUID каждой колонки, уникальность имён и непустые `Реквизиты`.
- Каждый реквизит должен существовать у указанного источника из `Состав`.
- Для запроса к таблице журнала используй поля по виду состава:
  - только документы: `Ссылка`, `Дата`, `Номер`, `Тип` и объявленные колонки;
  - только справочники: `Ссылка`, `ПометкаУдаления`, `Наименование`, `Код`, `Тип`, `КлючЗаписи` и колонки;
  - смешанный состав: `Ссылка`, `ПометкаУдаления`, `Тип`, `КлючЗаписи` и колонки.

Negative:

- Не обращайся к `Дата`, `Номер`, `Наименование`, `Код` как к стандартным
  полям смешанного журнала.

Примеры запросов из [документации Element 10.0](https://1cmycloud.com/console/help/element/10.0/docs/topics/data-journal-project-element/):

```xbql
ВЫБРАТЬ ЖурналДокументов.Ссылка, ЖурналДокументов.Дата, ЖурналДокументов.Номер
ИЗ ЖурналДокументов КАК ЖурналДокументов
```

```xbql
ВЫБРАТЬ ЖурналСправочников.Ссылка, ЖурналСправочников.Наименование, ЖурналСправочников.Код
ИЗ ЖурналСправочников КАК ЖурналСправочников
```

```xbql
ВЫБРАТЬ ОбщийЖурнал.Ссылка, ОбщийЖурнал.Тип, ОбщийЖурнал.КлючЗаписи, ОбщийЖурнал.ОбщаяКолонка
ИЗ ОбщийЖурнал КАК ОбщийЖурнал
```
