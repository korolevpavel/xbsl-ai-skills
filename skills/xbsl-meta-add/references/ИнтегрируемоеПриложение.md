# Спецификация: ИнтегрируемоеПриложение

## Назначение

Факты платформы:

- Элемент описывает подключение к одному внешнему приложению Element 10.0.
- `НастройкиПрямогоПодключения` — системный реквизит, добавляется платформой.
  Его поля `Адрес`, `ИдКлиента`, `СекретКлиента` заполняются в запущенном
  приложении, а не в YAML проекта.
- Для автоматической передачи сообщений план обмена ссылается на этот элемент
  в `ПередачаДанных.ИнтегрируемыеПриложения[].Имя`.

Соглашения генератора:

- Создавай элемент только в проекте приложения, которое будет инициировать
  соединение. Если оба приложения должны инициировать обмен, создай элемент
  в обоих проектах.
- Секреты подключения не сохраняй в исходниках.

## Версия

- Минимальная версия платформы: 10.0+.

## YAML

Required:

```yaml
ВидЭлемента: ИнтегрируемоеПриложение
Ид: <UUID>
Имя: <Имя>
ОбластьВидимости: ВПроекте
РежимУдаления: Немедленно
Реквизиты:
  - Имя: Наименование
```

Это минимальный пример из [документации обмена](https://1cmycloud.com/console/help/element/10.0/docs/topics/exchange-example/).
`ИмяВИнтегрируемомПриложении` задавай только при необходимости сопоставить
разные имена во внешнем проекте.

Negative:

- Не объявляй `НастройкиПрямогоПодключения` как пользовательский реквизит.
- Не помещай `Адрес`, `ИдКлиента`, `СекретКлиента` в YAML.

## UUID

Required:

- UUID получает сам элемент.

Negative:

- Не добавляй UUID системному реквизиту прямого подключения.

## Imports и visibility

Required:

- Если план обмена расположен в другой подсистеме, выбери область видимости
  `ВПроекте` и добавь нужный `Импорт` для ссылки из плана.

Negative:

- Не полагайся на короткое имя, если оно неоднозначно в проекте.

## Companion artifacts

Required:

- `<Имя>.yaml` — единственный обязательный файл.

Negative:

- Модуль `.xbsl` не нужен для минимального подключения.

## Генерация

Required:

- Создай описание интегрируемого приложения и план обмена с
  `ПередачаДанных.Использовать: Истина` только на стороне инициатора.
- На стороне получателя создай план обмена с тем же составом. Если имена
  планов различаются, используй
  `ИмяПланаОбменаВИнтегрируемомПриложении` для сопоставления.
- После запуска приложения создай экземпляр интегрируемого приложения и
  заполни адрес и ключ доступа сервисного пользователя внешнего приложения.
  Получателю нужны права чтения и записи объектов в составе плана обмена.

Negative:

- Не ставь `ПередачаДанных.Использовать: Истина` на получателе, если он не
  должен сам инициировать обмен.

## Валидация

Required:

- У элемента валидный UUID и имя; системный реквизит отсутствует в `Реквизиты`.
- Каждый `ПланОбмена.ПередачаДанных.ИнтегрируемыеПриложения[].Имя`
  разрешается в локальный элемент вида `ИнтегрируемоеПриложение`.
- В режиме выполнения убедись, что выбраны экземпляр интегрируемого
  приложения и активный узел. Платформа создаёт задание на каждый активный узел.

Negative:

- Не считай наличие YAML достаточным для подключения: настройки адреса и
  сервисного пользователя задаются в запущенном приложении.
