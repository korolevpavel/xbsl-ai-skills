# Спецификация: КлючДоступа

Контракт целевой платформы 1С:Предприятие.Элемент 9.3.

## Дефолты

- **Имя** — PascalCase и описывает контекст (`КлючДоступаМенеджера`, `КлючДоступаСотрудника`).
- **Видимость** — `ВПроекте`.
- **РучнаяВыдача** — `Ложь`. Отсутствующее поле эквивалентно `Ложь`.
- **ОтключитьСистемныеПересчеты** — официального default нет; добавляй поле только по явному запросу.

## UUID

Нужен: 1 (объект) + по 1 на каждый параметр, определённый разработчиком.
Системный параметр `Владелец` UUID не требует.

Пользовательский параметр всегда содержит `Ид`, `Имя` и `Тип`. Стандартный
параметр `Владелец` содержит только `Имя` и `Тип`, без `Ид`.

## Режимы

| Режим | `РучнаяВыдача` | `ОтключитьСистемныеПересчеты` | Handler и пересчёты |
|---|---|---|---|
| Автоматический, default | отсутствует или `Ложь` | отсутствует | `ПроверитьНаличиеКлючейДоступа`, системные и явные пересчёты |
| Автоматический, управляемый | `Ложь` | `Истина` | handler сохраняется, системные вызовы отключены, прикладной код вызывает пересчёты сам |
| Ручной | `Истина` | отсутствует | handler отсутствует, пересчёты ключа не выполняются, используются выдача и отзыв |
| Некорректный | `Истина` | поле присутствует с любым значением | ошибка контракта |

## YAML

Автоматический ключ с пользовательским параметром:

```yaml
ВидЭлемента: КлючДоступа
Ид: <UUID>
Имя: <ИмяКлюча>
ОбластьВидимости: ВПроекте
РучнаяВыдача: Ложь
Параметры:
    -
      Имя: Владелец
      Тип: Сотрудники.Ссылка?
    - Ид: <UUID>
      Имя: УровеньДоступа
      Тип: УровниДоступа
```

Для управляемого автоматического режима добавь
`ОтключитьСистемныеПересчеты: Истина`. Для ручного режима задай
`РучнаяВыдача: Истина` и не добавляй `ОтключитьСистемныеПересчеты`.

## Companion artifact

Для автоматического ключа допустим одноимённый optional `<ИмяКлюча>.xbsl` с
аннотированным обработчиком `ПроверитьНаличиеКлючейДоступа`. Он не обязателен:
валидатор не должен требовать handler у автоматического ключа.

Для ручного ключа этот обработчик не создавай. Одноимённый companion с другими
методами допустим, но handler автоматического расчёта будет проигнорирован и
диагностируется warning `owner.access_key.manual_handler_ignored`.

## API ручной выдачи

Методы ниже доступны только при `РучнаяВыдача: Истина`:

```xbsl
<Ключ>.ОтозватьКлючи(
    Пользователи: ЧитаемаяКоллекция<Пользователи.Ссылка>? = Неопределено)

<Ключ>.ОтозватьКлючи(
    Пользователи: ЧитаемаяКоллекция<Пользователи.Ссылка>? = Неопределено,
    <Параметр1>: <ТипПараметра1>,
    ...)

<Ключ>.Объект.Выдать(
    Пользователи: ЧитаемаяКоллекция<Пользователи.Ссылка>)

<Ключ>.Объект.Отозвать(
    Пользователи: ЧитаемаяКоллекция<Пользователи.Ссылка>? = Неопределено)

Пользователи.ВыдатьКлючиДоступа(
    ПользователиПоКлючам:
        ЧитаемоеСоответствие<
            КлючДоступа.Объект,
            ЧитаемаяКоллекция<Пользователи.Ссылка>>)
```

Размещай `Выдать`, `Отозвать`, `ОтозватьКлючи` и bulk-выдачу в документированных
бизнес-событиях, где изменяется связь пользователя с контекстом доступа.

## Пересчёты

Существующие методы не deprecated:

- `<Ключ>.ПересчитатьКлючи()`;
- `<Ключ>.Объект.Пересчитать()`;
- `Пользователи.ПересчитатьКлючиДоступа()`.

В 9.3 они пропускают ключи с ручной выдачей. Это не отменяет пересчёты
разрешений сущностей `ПересчитатьРазрешенияДоступа*`.

## Проверка прав

Доступ к сущностям задавай через `РазрешениеДоступа` и обработчики расчёта
разрешений. Для общего права используй документированные
`КонтрольДоступа.ЕстьПраво(...)` или `КонтрольДоступа.ПроверитьПраво(...)`, а не
ручную проверку экземпляра ключа.
