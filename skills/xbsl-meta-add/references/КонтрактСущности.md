# Спецификация: КонтрактСущности

## Назначение

Platform facts:

- `ВидЭлемента: КонтрактСущности` описывает свойства, которые должны
  присутствовать у реализующих сущностей.
- `ТаблицыКонтракта` управляет доступностью таблиц контракта в запросах.
- `Свойства[]` задают имя, тип, ограничения и `ТолькоЧтение`.
- Для read-write свойства реализация должна точно соответствовать типу и
  ограничениям; для read-only свойства источник допускает безопасное сужение.

Local conventions:

- Правила табличных частей не копируются сюда; используй
  `references/ТабличныеЧасти.md`.
- Реализующий объект не является обязательным companion генерируемого
  контракта.

## Версия

- Минимальная версия платформы: 9.1+.

## YAML

Required:

```yaml
ВидЭлемента: КонтрактСущности
Ид: <UUID>
Имя: <ИмяКонтракта>
ОбластьВидимости: ВПодсистеме
Свойства:
    -
        Ид: <UUID>
        Имя: <ИмяСвойства>
        Тип: <Тип>
        ТолькоЧтение: Ложь
```

Optional:

- `НастройкиТипов.КонтрактСущности.Объект.Контракты` задает базовые контракты
  объектного типа.
- `ТаблицыКонтракта` принимает `Доступны` или `Недоступны`; default
  `Недоступны`.
- `ПараметрыЗаписи` и `ПараметрыУдаления` содержат элементы с `Имя` и `Тип`.
- В target 10.0+ `ПолучениеВсехОдиночек: Доступно` разрешает статический
  `ПолучитьОдиночки()` у порождённого типа контракта; `Недоступно` не даёт
  этого метода. Включай `Доступно` только когда нужен обход всех реализаций.

Negative:

- Не создавай свойства `Ссылка` и `Представление`.
- Не смешивай свойства самого контракта с реквизитами реализации.

## UUID

Required:

- UUID получает `КонтрактСущности`.
- UUID получает каждый элемент `Свойства[]`.
- UUID табличных частей и их реквизитов считай по
  `references/ТабличныеЧасти.md`.

Negative:

- Системные свойства, порождаемые платформой, не получают YAML UUID в local
  generation workflow.

## Imports и visibility

Required:

- `ОбластьВидимости` задавай явно.
- Ссылочные типы проверяй через `references/types.md` и межподсистемный
  workflow skill.

Negative:

- Не добавляй `Импорт` без фактической ссылки на внешний namespace.

## Companion artifacts

Required:

- `*.yaml` - описание контракта сущности.

Optional (target 10.0+, когда объявлены методы контракта):

- `<ИмяКонтракта>.Объект.xbsl` — модуль контракта сущности с объявлениями
  `абстрактный метод`. Для реализующей сущности добавь её собственный
  `<ИмяСущности>.Объект.xbsl` с `@Реализация` и тем же методом.

Negative:

- Собственного обязательного `.xbsl` companion у минимального контракта
  сущности нет.
- Test-only реализующий объект не становится частью пользовательской генерации.

## Генерация

Required:

- Skill создает `<Имя>.yaml`.
- При табличных частях используй общий shared reference и не дублируй его
  правила в object-specific output.

Local conventions:

- Если пользователь просит пример реализации, добавляй отдельный `Справочник`,
  реализующий контракт через `НастройкиТипов.Справочник.Объект.Контракты`.

Для контракта с методом (target 10.0+) используй отдельные модули. В примере
`Сотрудники` реализует `УчастникиОповещений.Объект`:

```yaml
# УчастникиОповещений.yaml — дополнение к минимальному YAML
ПолучениеВсехОдиночек: Доступно
```

```xbsl
// УчастникиОповещений.Объект.xbsl
абстрактный метод Оповестить()
```

```yaml
# Сотрудники.yaml — фрагмент
НастройкиТипов:
    Справочник.Объект:
        Контракты:
            - УчастникиОповещений.Объект
```

```xbsl
// Сотрудники.Объект.xbsl
@Реализация
метод Оповестить()
    // Реализация для сотрудника.
;
```

`ПолучитьОдиночку(Источник)` принимает объект/ссылку реализующей сущности
или тип её объекта/ссылки. Его вызов не зависит от
`ПолучениеВсехОдиночек`. `ПолучитьОдиночки()` доступен только при
`ПолучениеВсехОдиночек: Доступно`:

```xbsl
метод ОповеститьОдного(Сотрудник: Сотрудники.Ссылка)
    пер Обработчик = УчастникиОповещений.ПолучитьОдиночку(Сотрудник)
    Обработчик.Оповестить()
;

метод ОповеститьВсех()
    для Обработчик из УчастникиОповещений.ПолучитьОдиночки()
        Обработчик.Оповестить()
    ;
;
```

Без `Доступно` не предлагай обход `ПолучитьОдиночки()`. Для простого
контракта без методов не создавай `.Объект.xbsl`.

Источники 10.0: [типы контракта и модуль](https://1cmycloud.com/console/help/element/10.0/docs/topics/contract-entity-type/), [пример имени файла и реализации](https://1cmycloud.com/console/help/element/10.0/docs/topics/working-with-contract-table-examples/), [свойство элемента](https://1cmycloud.com/console/help/element/10.0/docs/stdlib/element/ProjectElements/Std/ProjectElements/EntityContract/), [методы одиночек](https://1cmycloud.com/console/help/element/10.0/docs/stdlib/element/xbsl/DeveloperName/ProjectName/SubsystemName/EntityContractName_ru/).

Negative:

- Не создавай ручные порождаемые типы контракта.

## Валидация

Required:

- Read-write свойства реализации точно совпадают с контрактом по типу и
  ограничениям.
- Табличная часть реализации совместима с табличной частью контракта.
- Для метода контракта проверь одноимённую реализацию в модуле объекта
  реализующей сущности и её `@Реализация`.
- Перед примером `ПолучитьОдиночки()` проверь YAML-свойство
  `ПолучениеВсехОдиночек: Доступно`.

Negative:

- `incompatible_property`.
- `incompatible_tabular_section`.
