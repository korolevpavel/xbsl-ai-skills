# Спецификация: ПараметрСамостоятельнойРегистрацииПользователя

## Назначение

Platform facts:

- `ВидЭлемента: ПараметрСамостоятельнойРегистрацииПользователя` передает
  процессу самостоятельной регистрации данные, подготовленные до начала
  регистрации.
- `Поля[]` описывает поля параметра; подтвержденный пример использует `Имя` и
  `Тип`.
- Элемент имеет предопределенные обработчики: `ПослеПодключения()` обязателен,
  `ПриПроверкеПараметра(Логин: Строка?, Контакты: ЧитаемоеСоответствие<ВидКонтактаПользователя, Строка>): Булево`
  необязателен.

Local conventions:

- Минимальная генерация не создает форму регистрации, пользователя, роль,
  список пользователей или настройки контроля доступа.
- Модуль-скелет обязан быть безопасным и не менять production state.

## Версия

- Минимальная версия платформы: 9.1+.

### Регистрация и самообслуживание в 10.0

`ПараметрСамостоятельнойРегистрацииПользователя` остаётся опциональным элементом для дополнительных данных. В 10.0 `ОперацииСамообслуживания` предоставляет два новых метода на клиенте: `ПошаговаяРегистрацияСЛогином()` и `ПошаговаяРегистрацияСВнешнейУчетнойЗаписью()`. Оба возвращают отдельный объект операции; `Начать(УстановкаПараметраОбязательна = Истина|Ложь)` вызывай с **именованным** аргументом. Если аргумент `Истина`, до `Завершить()` обязателен `УстановитьПараметр(<экземпляр параметра>)`; при `Ложь` вызывать его нельзя. Каждый шаг возвращает статус: проверяй `ПредыдущийШагУспешен`, `Сообщение` и `ОжидаемыеДанные` перед следующим действием.

| Способ | Последовательность пользовательских шагов |
|---|---|
| Логин и пароль | `Начать` → `УстановитьЛогин` → `УстановитьПароль` → опциональный `УстановитьПараметр` → `УстановитьКонтакт` → ввод кода и `ПодтвердитьКонтакт` → `Завершить` |
| Внешняя учётная запись | `Начать` → `Аутентифицироваться(ПоставщикАутентификации)` → опциональный `УстановитьПараметр` → `Завершить` |

Логин, пароль и параметр могут устанавливаться после `Начать` в ином порядке; код можно подтверждать только после `УстановитьКонтакт`. Для внешней учётной записи аутентификация и установка параметра могут меняться местами. `Завершить()` создаёт и подключает пользователя; при наличии параметра вызывает `ПриПроверкеПараметра` и затем `ПослеПодключения`. Не вызывай `Завершить()` при неуспешном шаге или до выполнения требуемых подтверждений. [Операция с логином](https://1cmycloud.com/console/help/element/10.0/docs/stdlib/element/xbsl/Std/Users/SelfService/StepwiseRegistrationWithLoginOperation_ru/) · [внешняя запись](https://1cmycloud.com/console/help/element/10.0/docs/stdlib/element/xbsl/Std/Users/SelfService/StepwiseRegistrationWithExternalAccountOperation_ru/) · [статус](https://1cmycloud.com/console/help/element/10.0/docs/stdlib/element/xbsl/Std/Users/SelfService/SelfServiceStepwiseOperationStatus_ru/).

**Готовая страница регистрации** доступна по `/self-registration`. Если нужен собственный экран, используй `КомпонентСамостоятельнойРегистрации` внутри неаутентифицированного клиентского приложения; он сам ведёт ввод логина и пароля, подтверждение контакта и внешнюю аутентификацию. В 10.0 свойство `ОтображатьФормуРедактированияПользовательскихДанныхОтдельно` позволяет вынести форму дополнительных данных на отдельный шаг. Добавляй `ФормаРедактированияПользовательскихДанных` только при реальном пользовательском параметре; её реализация должна предоставлять `ПользовательскиеДанныеВалидны()` и `ПолучитьДанныеПользователя()`. [Пример формы](https://1cmycloud.com/console/help/element/10.0/docs/topics/self-registration-form/).

```yaml
ВидЭлемента: КомпонентИнтерфейса
Ид: <UUID>
Имя: ПриложениеРегистрации
ОбластьВидимости: ВПроекте
Наследует:
    Тип: ПроизвольноеКлиентскоеПриложение
    Путь: custom-self-registration
    РежимАутентификации: НеАутентифицированный
    Содержимое:
        Тип: КомпонентСамостоятельнойРегистрации
        Имя: КомпонентРегистрации
```

Для уже авторизованного пользователя в 10.0 можно встроить **форму самообслуживания** через `НавигационнаяКоманда` с `ТипФормы: ФормаСамообслуживания` в аутентифицированном клиентском приложении. Это отдельный сценарий от самостоятельной регистрации; компонент не создаётся автоматически как companion параметра. [Пример](https://1cmycloud.com/console/help/element/10.0/docs/topics/self-service-operations/).

Пользовательские соглашения, заданные в `Проект.yaml`, платформа показывает на страницах входа и регистрации. Не заменяй ими обязательный шаг подтверждения контакта и не придумывай для операций неописанный метод «согласия»: доступный API его не содержит.

## YAML

Required:

```yaml
ВидЭлемента: ПараметрСамостоятельнойРегистрацииПользователя
Ид: <UUID>
Имя: <ИмяПараметра>
ОбластьВидимости: ВПодсистеме
Поля:
    -
        Имя: <ИмяПоля>
        Тип: <Тип>
```

Negative:

- Не добавляй `Ид` внутрь `Поля[]`, пока контракт объекта не фиксирует такое
  свойство.
- Не создавай UI-компонент или настройки самостоятельной регистрации как
  companion этого объекта.

## UUID

Required:

- UUID получает сам объект
  `ПараметрСамостоятельнойРегистрацииПользователя`.

Negative:

- `Поля[]` в подтвержденных примерах не получают собственного UUID.

## Imports и visibility

Required:

- `ОбластьВидимости` задавай явно; подтвержденные примеры используют
  `ВПодсистеме`.
- `Импорт` добавляй только для типов из внешних пространств имен.

Negative:

- Не добавляй `Импорт` для встроенных типов `Строка`, `Дата` или `Ууид`.

## Companion artifacts

Required:

- `*.yaml` - описание параметра самостоятельной регистрации.
- `*.xbsl` - одноименный модуль с обязательным обработчиком
  `ПослеПодключения()`.

Negative:

- `ПриПроверкеПараметра(...)` не является обязательным обработчиком.
- Форма регистрации и клиентское приложение не являются обязательными
  companion-артефактами этого объекта.

## Генерация

Required:

- Skill создает `<Имя>.yaml` и `<Имя>.xbsl`.
- Модуль содержит `@Обработчик` и `метод ПослеПодключения()`.
- Опциональный `ПриПроверкеПараметра(...)` добавляй только по запросу
  пользователя.

Local conventions:

- В безопасном skeleton `ПослеПодключения()` оставляй без действий, если
  пользователь не описал нужное подключение.

Negative:

- Не записывай пользователя, роль, список пользователей или объект приложения
  без явного запроса и проверки проекта.

## Валидация

Required:

- `ВидЭлемента` равен
  `ПараметрСамостоятельнойРегистрацииПользователя`.
- `Поля[]` непустой список с `Имя` и `Тип`.
- Одноименный модуль содержит обязательный обработчик `ПослеПодключения()`.

Negative:

- `missing_required_handler`.
