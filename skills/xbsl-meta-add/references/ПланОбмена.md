# Спецификация: ПланОбмена

## Назначение

Факты платформы:

- `ВидЭлемента: ПланОбмена` описывает состав объектов, участвующих в обмене.
- В `Состав[]` указывается элемент конфигурации, включенный в план.
- Начиная с 10.0, опциональная `ПередачаДанных` описывает автоматическую
  передачу через `ИнтегрируемоеПриложение`. Минимальный локальный план без этой
  секции остаётся допустимым.

Соглашения генератора:

- Имя задавай PascalCase по сценарию обмена.
- Минимальный пример держит локальный элемент рядом, чтобы ссылка состава разрешалась.

При запросе настройки «Избранного» для target 10.0+ используй `references/Избранное.md`: свойство ставится на верхнем уровне YAML плана обмена.

## Версия

- Минимальная версия платформы: 9.1+.

## YAML

Required:

```yaml
ВидЭлемента: ПланОбмена
Ид: <UUID>
Имя: <Имя>
ОбластьВидимости: ВПодсистеме
Состав:
    -
        Элемент: <ИмяЭлемента>
```

Если текущий проект инициирует обмен с внешним приложением на Element 10.0,
добавь к плану:

```yaml
ПередачаДанных:
  Использовать: Истина
  ВидПакетаПередачиДанных: ВсеИзменения
  ИнтегрируемыеПриложения:
    - Имя: <ИмяЛокальногоИнтегрируемогоПриложения>
      ИмяПланаОбменаВИнтегрируемомПриложении: <ИмяВнешнегоПланаЕслиОтличается>
```

`ВидПакетаПередачиДанных` и имя внешнего плана можно опустить. Допустимые
виды пакета: `ВсеИзменения` (по умолчанию, сбой откатывает весь пакет) и
`ОдноИзменение` (сбой одного изменения не отменяет остальные).
На стороне получателя при одном инициаторе секция `ПередачаДанных` не нужна:
обмен всё равно идёт в две стороны через соединение инициатора.

Negative:

- Не оставляй `Состав[]` без `Элемент`.
- Не ссылайся на элемент, которого нет в проекте или комплекте примера.
- Не требуй `ИнтегрируемоеПриложение` для плана без автоматической передачи.

## UUID

Required:

- UUID получает объект плана обмена.
- Строки `Состав[]` в подтвержденном минимальном контракте не получают UUID.

Negative:

- Не добавляй UUID строкам состава без явного правила в контракте объекта.

## Imports и visibility

Required:

- `ОбластьВидимости` задавай явно.
- Если элемент состава находится в другой подсистеме, используй общий workflow `Импорт`/`Использование`/`ВПроекте`.
- При автоматической передаче проверь видимость интегрируемого приложения для
  плана обмена.

Negative:

- Не создавай план обмена с неразрешимой ссылкой состава.

## Companion artifacts

Required:

- `*.yaml` - описание объекта.

Negative:

- XBSL/XBQL companion не является обязательным для минимального плана обмена.

## Генерация

Required:

- Skill создает YAML плана и проверяет, что каждый `Состав[].Элемент` найден.
- При `ПередачаДанных.Использовать: Истина` проверяет, что каждое имя из
  `ИнтегрируемыеПриложения` разрешается в локальный элемент
  `ИнтегрируемоеПриложение`.
- Для двух приложений создай сопоставимые планы обмена с одинаковым составом.
  Одно приложение может быть единственным инициатором; для двух инициаторов
  настрой подключение в обоих проектах. В получателе сервисному пользователю
  требуются права чтения и записи элементов состава.
- Если элемент не найден, останавливайся или предлагай создать его отдельно.

Negative:

- Не создавай фиктивный объект состава молча в пользовательском проекте.

## Валидация

Required:

- `Состав` непустой список.
- Каждый `Элемент` разрешается внутри проекта.
- При включённой передаче список `ИнтегрируемыеПриложения` непустой, его ссылки
  разрешаются и не указывают на элемент другого вида.
- При разных именах планов укажи
  `ИмяПланаОбменаВИнтегрируемомПриложении` и проверь соответствие в обоих проектах.

Negative:

- `unresolved_composition`.
- Не записывай Client-ID и Client-Secret в исходный YAML.
