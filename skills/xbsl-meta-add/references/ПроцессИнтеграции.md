# Спецификация: ПроцессИнтеграции

## Назначение

Platform facts:

- `ВидЭлемента: ПроцессИнтеграции` декларативно описывает обмен между
  информационными системами.
- Основная часть процесса — `Схема`, состоящая из узлов, маршрутов, связей и
  групп участников.
- Узлы выполняют действия: возникновение сообщения, маршрутизацию,
  трансформацию, доставку.
- `Маршруты` описывают движение сообщения между узлами внутри приложения.
- `Связи` описывают движение сообщения между внешними информационными системами
  и узлами процесса.
- Узлы могут ссылаться на обработчики. Например, у узла `Транслятор` свойство
  `Преобразование` указывает метод модуля процесса.
- После публикации создается серверный тип `{ИмяПроцессаИнтеграции}` с
  методами `Запустить()`, `Остановить()` и `ОтправитьСообщениеВУзлы(...)`.
- В 10.0 узлы процесса проверяют **разрешения приложения**, которые настраиваются
  в панели управления и действуют сразу для запущенных процессов. Эти
  разрешения не являются полями YAML процесса.

Local conventions:

- Генерируй процесс только из структурированного описания пользователя.
- Не восстанавливай graph structure по screenshots или картинкам схемы.
- Если процесс содержит handler-backed nodes, создавай одноименный `.xbsl` с
  методами обработчиков.

## Версия

- Минимальная версия платформы: 9.1+.

## YAML

Required:

```yaml
ВидЭлемента: ПроцессИнтеграции
Ид: <UUID>
Имя: <ИмяПроцесса>
ОбластьВидимости: ВПодсистеме
СправочникУчастников: Общие::ИнформационныеСистемы
Схема:
    ГруппыУчастников:
        -
            Ид: <UUID>
            Имя: Партнеры
            X: 80
            Y: 120
            Высота: 60
            Ширина: 140
    Узлы:
        -
            Вид: ПрограммныйИсточник
            Ид: <UUID>
            Имя: ВходящиеЗаказы
        -
            Вид: Транслятор
            Ид: <UUID>
            Имя: НормализацияЗаказа
            Преобразование: NormalizeOrder
    Маршруты:
        -
            Ид: <UUID>
            Из: ВходящиеЗаказы
            В: НормализацияЗаказа
    Связи:
        -
            Ид: <UUID>
            Группа: Партнеры
            НаправлениеСвязи: ИзГруппыВУзел
            Узел: ВходящиеЗаказы
```

Optional:

- `Параметры[]` задает параметры процесса, используемые в выражениях схемы.
- Узлы конкретных видов добавляй только по подтвержденным свойствам их
  node-specific описаний.
- `РегистрироватьДоставкуВЖурналеСобытий`,
  `МаксимальноеКоличествоПовторныхДоставок` и
  `ТаймаутУстареванияНедоставленныхСообщений` используй только если они нужны в
  scenario.

Negative:

- Не создавай `Схема` без минимум двух узлов и маршрута между ними, если
  пользователь просит runnable flow.
- Не оставляй `Маршруты[].Из`, `Маршруты[].В`, `Связи[].Группа` или
  `Связи[].Узел` со значением, которого нет в этой же схеме.
- Не добавляй node properties, для которых нет явного описания в контракте.
- Не помещай разрешения приложения в `Схема` или свойства узла: настрой их
  в панели управления.

## UUID

Required:

- UUID получает сам объект `ПроцессИнтеграции`.
- UUID получают элементы схемы, у которых в YAML задано поле `Ид`: группы,
  узлы, маршруты и связи.

Negative:

- `Параметры[]` в подтвержденном YAML example не получают `Ид`.
- Методы обработчиков в `.xbsl` не получают YAML UUID.

## Imports и visibility

Required:

- `ОбластьВидимости` задавай явно; default платформы: `ВПодсистеме`.
- `Импорт` добавляй только для ссылок на справочник участников, сервисы,
  сообщения или типы из другой подсистемы.

Negative:

- Не добавляй `Импорт` для standard library types интеграционной шины.
- Не делай процесс `Глобально` без явного требования пользователя.

## Companion artifacts

Required:

- `*.yaml` - описание объекта вместе со схемой процесса.
- `*.xbsl` - одноименный модуль обработчиков процесса, когда схема содержит
  handler properties.

Negative:

- Отсутствующая `Схема` является ошибкой.
- Если в схеме есть `Преобразование` или другой handler property, одноименный
  `.xbsl` должен содержать метод с этим именем.

## Генерация

Required:

- Skill создает `<Имя>.yaml` со структурой `Схема`.
- Для handler-backed nodes создает `<Имя>.xbsl`.
- Для `Транслятор.Преобразование` генерируй метод с signature:

```xbsl
метод NormalizeOrder(Контекст: КонтекстВызоваИнтеграции,
                     Сообщение: СообщениеИнтеграции): СообщениеИнтеграции
    возврат Сообщение
;
```

Local conventions:

- Имена узлов внутри одного процесса должны быть уникальными.
- Имена обработчиков делай ASCII-friendly, если они могут участвовать во
  внешнем протоколе или generated API.
- При нехватке данных для конкретного node kind создай только каркас процесса и
  явно перечисли, какие node-specific свойства пользователь должен уточнить.
- Перед запуском/публикацией процесса проверь разрешения приложения для
  каждого источника и назначения в панели управления. Для узлов RabbitMQ,
  Kafka и JMS проверка выполняется при установке соединения. Если разрешений
  нет, не объявляй процесс готовым к доставке.

Negative:

- Не создавай параметры подключения, участника или чувствительные значения вместо ссылок
  на `Параметры[]` процесса.
- Не добавляй графические coordinates как единственный источник логики:
  маршруты и связи всегда должны ссылаться на имена узлов/групп.

## Валидация

Required:

- `ВидЭлемента` равен `ПроцессИнтеграции`.
- `Схема.Узлы`, `Схема.Маршруты` и `Схема.Связи` согласованы по именам.
- `Схема.ГруппыУчастников` согласована со всеми `Связи[].Группа`.
- Каждый handler property в схеме указывает существующий метод одноименного
  `.xbsl`.
- Для `Транслятор.Преобразование` метод возвращает `СообщениеИнтеграции`.
- Для внешних узлов проверь разрешения приложения по их ресурсу. Статический
  валидатор выдаёт `owner.integration_process.permissions_runtime`, пока
  состояние панели управления не проверено. Отсутствие разрешения на старте:
  источник не создаёт сообщения; назначение не отправляет их вовне и
  направляет поступившие сообщения в недоставленные **без повтора**. При
  отказе на маршруте сообщение тоже сразу становится недоставленным с
  причиной «Нет разрешения». В журнале событий ищи
  `ОшибкаПроверкиРазрешенийПроцессаИнтеграции` с узлом и ресурсом.
- «Нет разрешения» на стороне приложения отличается от «Доступ запрещен» при
  аутентификации или авторизации на удалённом сервисе.
- Для `ФайлИсточник` и `FtpИсточник` при действии после чтения «удалить» или
  «переименовать» проверь соответствующее разрешение. Если доступно только
  чтение, файл обрабатывается один раз и помещается в репозиторий
  идемпотентных файлов.

Negative:

- `missing_process_schema`.
- `unknown_process_node`.
- `unknown_participant_group`.
- `missing_process_module`.
- `handler_method_not_found`.
