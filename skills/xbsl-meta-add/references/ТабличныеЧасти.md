# Спецификация: Табличные части

Табличные части используются в `Справочник` и `Документ` для хранения списка строк, связанных с объектом.

## UUID

Каждая ТЧ требует отдельного UUID. Каждый реквизит ТЧ тоже требует UUID. Системных полей в ТЧ нет.

**Формула подсчёта:** +1 за ТЧ + по 1 за каждый реквизит ТЧ.

## Структура YAML

```yaml
ТабличныеЧасти:
    -
        Ид: <UUID>
        Имя: <ИмяТЧ>
        Реквизиты:
            -
                Ид: <UUID>
                Имя: <ИмяКолонки>
                Тип: <Тип>
            -
                Ид: <UUID>
                Имя: <ИмяКолонки2>
                Тип: <Тип>
```

## Правила

- `ТабличныеЧасти` располагается после `Реквизиты` объекта.
- Имя ТЧ — PascalCase, существительное во множественном числе (`Товары`, `Контакты`, `Услуги`).
- Реквизиты ТЧ подчиняются тем же правилам типов, что и реквизиты объекта:
  - Ссылочные поля и перечисления: `ИспользоватьВПолнотекстовомПоиске: Ложь`
  - Для строковых пользовательских полей: `НезаполненноеЗначение: Разрешить` или `ЗапретитьВсегда`
  - Числа: указывать `ДлинаЦелойЧасти`, `ДлинаДробнойЧасти`, `МинимальноеЗначение`
  - Строки: указывать `МаксимальнаяДлина`

## Владение, индексы и системные поля

Этот файл является shared reference: object references для `Справочник`,
`Документ`, `КонтрактСущности` и других типов с табличными частями должны
ссылаться на него через `shared_reference_paths`, а не копировать правила.

- Владельцем строки табличной части является объект, в YAML которого находится
  секция `ТабличныеЧасти`.
- Индексы, обязательные реквизиты и системные query-поля фиксируются только
  там, где object-specific reference ссылается на точный источник.
- Системные поля табличной части не получают UUID в local generation workflow,
  если object reference не содержит явного правила об обратном.
- Если объектная документация требует дополнительные индексы или обязательные
  реквизиты табличной части, эти требования описываются в object reference, а
  здесь остаётся общий контракт вложенности и UUID.

## Пример: ТЧ Товары

```yaml
ТабличныеЧасти:
    -
        Ид: <UUID>
        Имя: Товары
        Реквизиты:
            -
                Ид: <UUID>
                Имя: Номенклатура
                Тип: Номенклатура.Ссылка?
                ИспользоватьВПолнотекстовомПоиске: Ложь
            -
                Ид: <UUID>
                Имя: Количество
                Тип: Число
                ДлинаЦелойЧасти: 15
                ДлинаДробнойЧасти: 3
                МинимальноеЗначение: 0
            -
                Ид: <UUID>
                Имя: Цена
                Тип: Число
                ДлинаЦелойЧасти: 15
                ДлинаДробнойЧасти: 2
                МинимальноеЗначение: 0
            -
                Ид: <UUID>
                Имя: Сумма
                Тип: Число
                ДлинаЦелойЧасти: 15
                ДлинаДробнойЧасти: 2
                МинимальноеЗначение: 0
```

## Пример: ТЧ с контактами (справочник)

```yaml
ТабличныеЧасти:
    -
        Ид: <UUID>
        Имя: Контакты
        Реквизиты:
            -
                Ид: <UUID>
                Имя: ТипАдреса
                Тип: ТипыКонтактнойИнформации?
                ИспользоватьВПолнотекстовомПоиске: Ложь
            -
                Ид: <UUID>
                Имя: Значение
                Тип: Строка
                МаксимальнаяДлина: 200
```
