# RLS-паттерны для объектов 1С:Элемент

## Двухуровневая модель (обязательно оба уровня)

```
Уровень 1: доступ к таблице целиком       → ВычислитьРазрешенияДоступа()
                    ↓
Уровень 2: доступ к конкретной строке     → ВычислитьРазрешенияДоступаДляОбъектов()
```

> ❗ Нельзя получить доступ к строке, минуя уровень 1. Оба обработчика обязательны.
> **Правило**: все права, перечисленные в уровне 2, обязательно должны присутствовать и в уровне 1.

## Предопределённые ключи (файлы НЕ создаются, используются как есть)

| Ключ | Кому выдаётся |
|------|--------------|
| `КлючДоступаДляВсех` | Любому субъекту, включая неаутентифицированных |
| `КлючДоступаДляАутентифицированных` | Каждому вошедшему пользователю |
| `КлючДоступаПользователя(ПользовательСсылка)` | Конкретному пользователю по ссылке |

---

## Ограничения для полей РасчетРазрешенийПо

Поле, указанное в `РасчетРазрешенийПо`, должно соответствовать всем условиям:

| Требование | Допустимо | Недопустимо |
|------------|-----------|-------------|
| Тип данных | Ссылочные типы (`Справочник.Ссылка?`), числа, булево, дата | Коллекции (`Массив`, `Соответствие`) |
| Строки | Строка с ограниченной длиной | Строка без ограничения длины |
| Перечисления | Пользовательские перечисления | Системные/stdlib перечисления |

> Если поле не соответствует — платформа выдаст ошибку при расчёте разрешений.

## Паттерн P0: Без построчной фильтрации (простой доступ к таблице)

**Сценарий**: Все записи видны всем (или только администраторам). Строчная фильтрация не нужна.
Обработчики в `.xbsl` не создаются. Поле `РасчетРазрешенийПо` не указывается.

### YAML объекта — вариант А: все аутентифицированные

```yaml
КонтрольДоступа:
    Разрешения:
        ПоУмолчанию: РазрешеноАутентифицированным
```

### YAML объекта — вариант Б: только администраторы

```yaml
КонтрольДоступа:
    Разрешения:
        ПоУмолчанию: РазрешеноАдминистраторам
```

### YAML объекта — вариант В: разные правила для разных прав

```yaml
КонтрольДоступа:
    РасчетРазрешенийПо:
        - <ПолеКонтекста>
    Разрешения:
        Чтение: РазрешенияВычисляютсяДляКаждогоОбъекта   # строчный RLS только для Чтения
        Изменение: РазрешеноАдминистраторам               # Изменение — только администраторам
```

> Вариант В требует обработчики `ВычислитьРазрешенияДоступа` и `ВычислитьРазрешенияДоступаДляОбъектов`
> только для прав с `РазрешенияВычисляютсяДляКаждогоОбъекта`. Остальные права заданы явно.

## Паттерн P1: По пользователю (предопределённый ключ)

**Сценарий**: Каждый пользователь видит только свои записи.
Файлы КлючДоступа не создаются. UUID не нужны.

### YAML объекта (секция КонтрольДоступа)

```yaml
КонтрольДоступа:
    РасчетРазрешенийПо:
        - <ПолеПользователя>        # реквизит типа Пользователи.Ссылка?
    Разрешения:
        ПоУмолчанию: РазрешенияВычисляютсяДляКаждогоОбъекта
```

### Обработчик уровня 1 (весь справочник — чтение для аутентифицированных)

```xbsl
@Обработчик
метод ВычислитьРазрешенияДоступа(): Массив<РазрешениеДоступа>
    возврат [
        новый РазрешениеДоступа(
            [новый КлючДоступаДляАутентифицированных.Объект()],
            [Сущность.Право.Чтение]
        )
    ]
;
```

> Уровень 1 даёт только `Чтение`, поэтому в уровне 2 тоже должно быть не больше `Чтение`.
> Если пользователь должен изменять свои записи — добавь `Сущность.Право.Изменение` сюда тоже.

### Обработчик уровня 2 (каждый видит только свои строки)

```xbsl
@Обработчик
метод ВычислитьРазрешенияДоступаДляОбъектов(Объекты: ЧитаемыйМассив<<Объект>.ДанныеРасчетаРазрешений>): ЧитаемоеСоответствие<<Объект>.ДанныеРасчетаРазрешений, ЧитаемаяКоллекция<РазрешениеДоступа>>
    знч РазрешенияПоОбъектам = <<Объект>.ДанныеРасчетаРазрешений, ЧитаемаяКоллекция<РазрешениеДоступа>>{:}

    для Объект из Объекты
        если Объект.<ПолеПользователя> != Неопределено
            РазрешенияПоОбъектам.Вставить(Объект, [
                новый РазрешениеДоступа(
                    [новый КлючДоступаПользователя.Объект(Объект.<ПолеПользователя>)],
                    [Сущность.Право.Чтение]
                )
            ])
        ;
    ;

    возврат РазрешенияПоОбъектам
;
```

> Подставь реальное имя объекта вместо `<Объект>` (например: `Задачи`, `Аккаунты`).
> Подставь реальное имя реквизита вместо `<ПолеПользователя>` (например: `Пользователь`, `Ответственный`).
> Набор прав в уровне 2 должен совпадать с набором прав в уровне 1.
> ⚠️ Используй `!= Неопределено`, а не `= Неопределено` — в XBSL оператор `=` является только присваиванием и недопустим в условии `если`.

## Паттерн P2: По параметру (собственный ключ)

**Сценарий**: Группа пользователей видит записи, связанные с их контекстом
(организация, регион, подразделение и т. п.).
Создаётся один собственный `КлючДоступа`. UUID нужен на объект ключа и на
каждый пользовательский параметр. Стандартный параметр `Владелец` не имеет `Ид`.

### Режимы выдачи ключа

- `automatic` (default): `РучнаяВыдача` отсутствует или равна `Ложь`, handler
  сохраняется, доступны системные и явные пересчёты.
- `automatic-disabled`: `РучнаяВыдача: Ложь` и
  `ОтключитьСистемныеПересчеты: Истина`; handler сохраняется, а приложение
  вызывает пересчёты в документированных бизнес-событиях.
- `manual`: `РучнаяВыдача: Истина`; поле `ОтключитьСистемныеПересчеты`, handler
  `ПроверитьНаличиеКлючейДоступа` и пересчёты ключа запрещены.

### YAML ключа

```yaml
ВидЭлемента: КлючДоступа
Ид: <UUID>
Имя: <КлючИмя>
ОбластьВидимости: ВПроекте
РучнаяВыдача: Ложь               # можно опустить для automatic
Параметры:
    -
        Имя: Владелец
        Тип: <Справочник>.Ссылка?
```

> Пользовательский параметр содержит `Ид`, `Имя` и `Тип`. Только системный
> `Владелец` содержит `Имя` и `Тип`, без `Ид`.
> `ОбластьВидимости: ВПроекте` — ключ используется из нескольких подсистем.
> Если тип параметра (`<Справочник>`) из другой подсистемы — добавь `Импорт: [<Подсистема>]`.

### Вариант P2-б: Ключ без параметров (ролевой доступ)

Если доступ нужен не по конкретному объекту, а по роли пользователя — параметры не нужны:

```yaml
ВидЭлемента: КлючДоступа
Ид: <UUID>
Имя: <КлючИмя>
ОбластьВидимости: ВПроекте
РучнаяВыдача: Ложь               # Истина для manual
# Параметры отсутствуют — один экземпляр ключа на всё приложение
```

Для `automatic-disabled` добавь `ОтключитьСистемныеПересчеты: Истина`. Для
`manual` не добавляй это поле даже со значением `Ложь`.

Обработчик `ПроверитьНаличиеКлючейДоступа` проще — не нужно группировать по параметру:

```xbsl
@Обработчик
метод ПроверитьНаличиеКлючейДоступа(
        Ключи: ЧитаемыйМассив<<КлючИмя>.Объект>,
        Пользователи: ЧитаемыйМассив<Пользователи.Ссылка>
    ): ЧитаемоеСоответствие<<КлючИмя>.Объект, ЧитаемаяКоллекция<Пользователи.Ссылка>>

    знч Запрос = Запрос{
        ВЫБРАТЬ
            Пользователь
        ИЗ
            <ТаблицаСвязи>           // TODO: таблица, где хранится роль пользователя
        ГДЕ
            Пользователь В (%Пользователи)
            И <ПолеРоли> == <Роль>   // TODO: условие на роль
    }

    знч Владельцы = Запрос.Выполнить().Преобразовать(Строка -> Строка.Пользователь!)

    знч ПользователиПоКлючам = <<КлючИмя>.Объект, Массив<Пользователи.Ссылка>>{:}
    для Ключ из Ключи
        ПользователиПоКлючам.Вставить(Ключ, Владельцы)
    ;

    возврат ПользователиПоКлючам
;
```

Использование в уровне 2 — без аргументов:
```xbsl
новый <КлючИмя>.Объект()  // параметров нет
```

> Пример из vendor: `КлючДоступаРуководителя` — выдаётся всем, у кого `Роль == Руководитель`.

### XBSL ключа (ПроверитьНаличиеКлючейДоступа)

Этот companion создаётся только для `automatic` и `automatic-disabled`.
В режиме `manual` его не создавай.

```xbsl
@Обработчик
метод ПроверитьНаличиеКлючейДоступа(
        Ключи: ЧитаемыйМассив<<КлючИмя>.Объект>,
        Пользователи: ЧитаемыйМассив<Пользователи.Ссылка>
    ): ЧитаемоеСоответствие<<КлючИмя>.Объект, ЧитаемаяКоллекция<Пользователи.Ссылка>>

    знч Параметры = Ключи.Преобразовать(Ключ -> Ключ.Владелец)

    знч Запрос = Запрос{
        ВЫБРАТЬ
            Пользователь,
            <ПолеКонтекста>          // TODO: поле связи с параметром ключа (напр. Организация, Регион)
        ИЗ
            <ТаблицаСвязи>           // TODO: справочник/регистр «пользователь ↔ контекст» (напр. Сотрудники)
        ГДЕ
            <ПолеКонтекста> В (%Параметры)
            И Пользователь В (%Пользователи)
    }

    знч КлючиПоПараметру = <<Справочник>.Ссылка, Массив<Пользователи.Ссылка>>{:}  // TODO: тип параметра

    исп РезультатЗапроса = Запрос.Выполнить()
    для СтрокаРезультата из РезультатЗапроса
        КлючиПоПараметру
            .ВставитьЕслиОтсутствует(СтрокаРезультата.<ПолеКонтекста>, <Пользователи.Ссылка>[])
            .Добавить(СтрокаРезультата.Пользователь)
    ;

    знч ПользователиПоКлючам = <<КлючИмя>.Объект, Массив<Пользователи.Ссылка>>{:}
    для Ключ из Ключи
        ПользователиПоКлючам.Вставить(Ключ, КлючиПоПараметру.ПолучитьИлиУмолчание(Ключ.Владелец, []))
    ;

    возврат ПользователиПоКлючам
;
```

> `// TODO` — заглушки, которые разработчик заполняет под свою модель данных.
> Пример из vendor: `КлючДоступаСотрудникаОрганизации` → запрос к `Сотрудники` по полю `Организация`.

### Ручная выдача и отзыв

В `manual`-режиме размещай операции в подходящих бизнес-событиях:

```xbsl
знч ЭкземплярКлюча = новый <КлючИмя>.Объект(Владелец = Контекст)
ЭкземплярКлюча.Выдать(Пользователи)
ЭкземплярКлюча.Отозвать(Пользователи)
<КлючИмя>.ОтозватьКлючи(Пользователи, Владелец = Контекст)

знч ПользователиПоКлючам = <КлючДоступа.Объект, ЧитаемаяКоллекция<Пользователи.Ссылка>>{
    ЭкземплярКлюча: Пользователи
}
Пользователи.ВыдатьКлючиДоступа(ПользователиПоКлючам)
```

Не предлагай для manual key `<КлючИмя>.ПересчитатьКлючи()` или
`<КлючИмя>.Объект.Пересчитать()`. Методы пересчёта не deprecated, но в 9.3
пропускают ключи с `РучнаяВыдача: Истина`.

### YAML объекта (секция КонтрольДоступа)

```yaml
КонтрольДоступа:
    РасчетРазрешенийПо:
        - <ПолеКонтекста>           # реквизит типа <Справочник>.Ссылка?
    Разрешения:
        ПоУмолчанию: РазрешенияВычисляютсяДляКаждогоОбъекта
```

### Обработчик уровня 1 (все аутентифицированные видят таблицу)

```xbsl
@Обработчик
метод ВычислитьРазрешенияДоступа(): Массив<РазрешениеДоступа>
    возврат [
        новый РазрешениеДоступа(
            [новый КлючДоступаДляАутентифицированных.Объект()],
            [Сущность.Право.Изменение, Сущность.Право.Создание, Сущность.Право.Чтение, Сущность.Право.Удаление]
        )
    ]
;
```

> Если уровень 1 даёт все 4 права, то уровень 2 может давать любое их подмножество.

### Обработчик уровня 2 (доступ к строкам через ключ с параметром)

```xbsl
@Обработчик
метод ВычислитьРазрешенияДоступаДляОбъектов(Объекты: ЧитаемыйМассив<<Объект>.ДанныеРасчетаРазрешений>): ЧитаемоеСоответствие<<Объект>.ДанныеРасчетаРазрешений, ЧитаемаяКоллекция<РазрешениеДоступа>>
    знч РазрешенияПоОбъектам = <<Объект>.ДанныеРасчетаРазрешений, ЧитаемаяКоллекция<РазрешениеДоступа>>{:}

    для Объект из Объекты
        если Объект.<ПолеКонтекста> == Неопределено
            продолжить
        ;
        РазрешенияПоОбъектам.Вставить(Объект, [
            новый РазрешениеДоступа(
                [новый <КлючИмя>.Объект(Владелец = Объект.<ПолеКонтекста>)],
                [Сущность.Право.Изменение, Сущность.Право.Создание, Сущность.Право.Чтение, Сущность.Право.Удаление]
            )
        ])
    ;

    возврат РазрешенияПоОбъектам
;
```

> Подставь: `<Объект>` — имя справочника/документа; `<ПолеКонтекста>` — поле из `РасчетРазрешенийПо`;
> `<КлючИмя>` — имя созданного ключа.

## Паттерн P3: Несколько участников с разными правами

**Сценарий**: Объект доступен двум разным участникам (например, Заказчик и Исполнитель),
каждый получает свои права. Оба поля указываются в `РасчетРазрешенийПо`.
Файлы КлючДоступа не создаются — используется предопределённый `КлючДоступаПользователя`.

> Требование: каждый справочник-участник должен иметь реквизит типа `Пользователи.Ссылка`,
> через который и выполняется связь.

### YAML объекта (секция КонтрольДоступа)

```yaml
КонтрольДоступа:
    РасчетРазрешенийПо:
        - <Поле1>   # реквизит типа <Справочник1>.Ссылка? (содержит поле Пользователь)
        - <Поле2>   # реквизит типа <Справочник2>.Ссылка? (содержит поле Пользователь)
    Разрешения:
        ПоУмолчанию: РазрешенияВычисляютсяДляКаждогоОбъекта
```

### Обработчик уровня 1

```xbsl
@Обработчик
метод ВычислитьРазрешенияДоступа(): Массив<РазрешениеДоступа>
    возврат [
        новый РазрешениеДоступа(
            [новый КлючДоступаДляАутентифицированных.Объект()],
            [Сущность.Право.Изменение, Сущность.Право.Создание, Сущность.Право.Чтение, Сущность.Право.Удаление]
        )
    ]
;
```

### Обработчик уровня 2

```xbsl
@Обработчик
метод ВычислитьРазрешенияДоступаДляОбъектов(Объекты: ЧитаемыйМассив<<Объект>.ДанныеРасчетаРазрешений>): ЧитаемоеСоответствие<<Объект>.ДанныеРасчетаРазрешений, ЧитаемаяКоллекция<РазрешениеДоступа>>
    знч РазрешенияПоОбъектам = <<Объект>.ДанныеРасчетаРазрешений, ЧитаемаяКоллекция<РазрешениеДоступа>>{:}

    // Отдельный запрос для каждого типа участника
    знч <Поле1>Мн = Объекты.Преобразовать(Объект -> Объект.<Поле1>).Уникальные()
    знч Пользователи<Поле1> = Запрос{
        ВЫБРАТЬ
            Пользователь,
            Ссылка КАК <Поле1>
        ИЗ
            <Справочник1> КАК <Справочник1>
        ГДЕ
            Ссылка В (%<Поле1>Мн)
    }.Выполнить().ВСоответствие(Строка -> Строка.<Поле1>, Строка -> Строка.Пользователь)

    знч <Поле2>Мн = Объекты.Преобразовать(Объект -> Объект.<Поле2>).Уникальные()
    знч Пользователи<Поле2> = Запрос{
        ВЫБРАТЬ
            Пользователь,
            Ссылка КАК <Поле2>
        ИЗ
            <Справочник2> КАК <Справочник2>
        ГДЕ
            Ссылка В (%<Поле2>Мн)
    }.Выполнить().ВСоответствие(Строка -> Строка.<Поле2>, Строка -> Строка.Пользователь)

    для Объект из Объекты
        знч Разрешения = <РазрешениеДоступа>[]

        знч ПользовательПервогоУчастника = Объект.<Поле1> != Неопределено
            ? Пользователи<Поле1>.ПолучитьИлиНеопределено(Объект.<Поле1>)
            : Неопределено
        если ПользовательПервогоУчастника != Неопределено
            Разрешения.Добавить(
                новый РазрешениеДоступа(
                    [новый КлючДоступаПользователя.Объект(Владелец = ПользовательПервогоУчастника)],
                    [Сущность.Право.Изменение, Сущность.Право.Создание, Сущность.Право.Чтение]  // полные права для <Поле1>
                )
            )
        ;

        знч ПользовательВторогоУчастника = Объект.<Поле2> != Неопределено
            ? Пользователи<Поле2>.ПолучитьИлиНеопределено(Объект.<Поле2>)
            : Неопределено
        если ПользовательВторогоУчастника != Неопределено
            Разрешения.Добавить(
                новый РазрешениеДоступа(
                    [новый КлючДоступаПользователя.Объект(Владелец = ПользовательВторогоУчастника)],
                    [Сущность.Право.Чтение]  // только чтение для <Поле2>
                )
            )
        ;

        РазрешенияПоОбъектам.Вставить(Объект, Разрешения)
    ;

    возврат РазрешенияПоОбъектам
;
```

> Подставь: `<Объект>` — имя документа/справочника; `<Поле1>`, `<Поле2>` — имена реквизитов;
> `<Справочник1>`, `<Справочник2>` — их типы; права в каждом блоке — по бизнес-логике.
> Пример из vendor: `Заказ` → Заказчик (Создание+Чтение+Изменение) и Исполнитель (только Чтение).

## Пересчёт прав

### Первый пересчёт после деплоя

Добавь в `Проект.xbsl` метод с аннотацией обновления. `Ид` должен быть уникальным в проекте.
Если объект находится в подсистеме — добавь `импорт <Подсистема>` в начало `Проект.xbsl`:

```xbsl
импорт <Подсистема>   // обязателен, если объект не в корне проекта

@ОбновлениеПроекта(Ид = "recalc_<Объект>_rls_v1", Номер = N)
метод ПересчитатьПрава<Объект>()
    <Объект>.ПересчитатьРазрешенияДоступа()
    <Объект>.ПересчитатьРазрешенияДоступаДляОбъектов()
;
```

> Оба метода обязательны: `ПересчитатьРазрешенияДоступа()` — для уровня 1 (таблица),
> `ПересчитатьРазрешенияДоступаДляОбъектов()` — для уровня 2 (строки).

### Своевременный пересчёт при изменении данных (P2)

В `ПослеЗаписи` справочника/регистра, хранящего связь «пользователь ↔ контекст»:

```xbsl
// Если изменился контекст (организация, регион, подразделение пользователя)
если До.<ПолеКонтекста> != Это.<ПолеКонтекста>
    исп КонтекстДоступа.Привилегированный()
        <КлючИмя>.ПересчитатьКлючи(<Параметр> = Это.Ссылка)
;
```

> `КонтекстДоступа.Привилегированный()` — вызов с круглыми скобками, используется как блок `исп`.

### Пересчёт при изменении пользователей (P1 и P2)

Если пользователь был удалён, переименован или изменён — запусти пересчёт ключей пользователей:

```xbsl
// В ПослеЗаписи/ПослеУдаления обработчике объекта Пользователи
исп КонтекстДоступа.Привилегированный()
    Пользователи.ПересчитатьКлючиДоступа()
;
```
