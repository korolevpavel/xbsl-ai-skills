# Авторизация

`storageState` — непрозрачный файл: проверяй наличие пути и передавай его
Playwright. Не открывай JSON, не печатай cookies/storage и не прикладывай
сессию к отчёту. Для каждой роли используй отдельный state и context.

## Первый вход

Переиспользуй auth setup проекта, если он есть. Для нового проекта скопируй
[auth.mjs](../assets/auth.mjs) в его корень; команды `auth` и `auth:check`
есть в [package.json](../assets/package.json). Добавь `.auth/` в `.gitignore`
до входа. Playwright и Chromium должны быть установлены локально.

Задай **полный URL пользователя** отдельной командой; не совмещай присваивание
переменной и раскрытие её прежнего значения в одном shell-вызове. Пример POSIX:

```bash
export ELEMENT_APP_URL='https://example.com/applications/my-app'
export ELEMENT_AUTH_STATE='.auth/user.json'
npm run auth
```

В PowerShell используй `$env:ELEMENT_APP_URL = 'полный URL'` и аналогично
для остальных переменных. Передай те же значения каждому следующему запуску:
отдельные tool-вызовы могут иметь независимое окружение. Если браузер уже
установлен отдельно, задай `ELEMENT_EXECUTABLE_PATH` для auth и тестов одинаково.

Запускай `npm run auth` в интерактивной PTY и сохрани process/session ID.
Helper открывает одно окно браузера. Пользователь вводит секреты в браузере,
дожидается рабочей страницы и сообщает о готовности; тогда передай **Enter**
этому процессу. Сам пользователь также может нажать Enter в терминале.
Не закрывай окно и не посылай Ctrl+C для сохранения. Пока идёт вход, не снимай
DOM, trace или screenshot и не читай clipboard/password manager. Дополнительное
подтверждение уже разрешённого входа и локального сохранения не требуется.

Helper сохраняет state до закрытия context, затем проверяет его в свежем
context. Если известен наблюдённый уникальный элемент рабочей страницы,
передай `ELEMENT_READY_SELECTOR`. Иначе helper попробует единственный видимый
`h1` после входа и проверит **этот же точный текст** после нового открытия.
Выведенный selector сохрани в README проекта для следующих запусков.

## Проверка и восстановление

`AUTH PASS` требует видимого элемента приложения в свежем context. State-файл,
смена URL или рабочее первое окно сами по себе успех не доказывают.

Если state сохранён, но heading неоднозначен, helper завершится с `AUTH UNVERIFIED`.
Выбери selector из реально наблюдённой рабочей страницы, задай
`ELEMENT_READY_SELECTOR` и запусти `npm run auth:check`. Существующую сессию
можно проверить так же; повторный ручной вход для уточнения selector не нужен.
Не используй `body`, общий контейнер или элемент, присутствующий также на login.

Если свежий context снова показывает вход — `BLOCKED/AUTH`; 5xx, неверный URL
или отсутствие браузера — `BLOCKED/ENVIRONMENT`. Отдельно проверь ошибку
selector: timeout не доказывает дефект приложения. Отмена/EOF до Enter не
сохраняет сессию. Ошибка сохранения или проверки завершает helper с nonzero exit.

Обычный state не сохраняет `sessionStorage`. Если оно необходимо, переиспользуй
механизм проекта и проверь свежий context; без воспроизводимого восстановления —
`BLOCKED/AUTH`. Правила evidence: [run-and-debug.md](run-and-debug.md).
