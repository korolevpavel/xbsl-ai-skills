# Создание и изменение тестов

## Setup

Определи ближайший Node-проект по `package.json`, `packageManager`, workspace и
lockfile. Существующие Playwright config, версии, fixtures, Page Objects,
reporters и testDir сохраняй. Не создавай второй scaffold рядом с работающим.
При конфликтующих lockfiles в одной точке владения уточни package manager;
если проекта нет, используй npm в отдельном `e2e/`.

Новый пакет `e2e/` изолируй от корневого workspace: скопируй
[package.json](../assets/package.json), [config](../assets/playwright.config.ts)
и [auth.mjs](../assets/auth.mjs) в его корень, создай `tests/`.
Шаблон фиксирует проверенную версию; не выбирай другую из памяти.
Из каталога нового пакета последовательно выполни:

```sh
npm install
npm exec -- playwright install chromium
```

Дождись успешного завершения каждой команды. 100% скачивания ещё не означает
готовый браузер. При ошибке проверь сообщение и совпадение версии пакета/браузера;
не запускай параллельные установки, не удаляй lock активного installer и не
собирай cache вручную. После двух неудачных попыток — `BLOCKED/ENVIRONMENT`.
Существующий совместимый браузер можно передать через `ELEMENT_EXECUTABLE_PATH`.
Зависимости и браузер — разрешённая подготовка тестирования. Сохрани lockfile,
не меняй корневой lockfile consumer-проекта и каталог самого скилла.
Если manager поднимается к workspace root, используй его изолированный режим.

Основа нового config — [playwright.config.ts](../assets/playwright.config.ts).
Его дефолты:

- Chromium, один worker, `retries: 0`;
- полный `ELEMENT_APP_URL` как `baseURL`, ошибка при его отсутствии;
- `trace: "off"`, `video: "off"`, `screenshot: "only-on-failure"`;
- reporters `list` и HTML (`open: "never"`);
- уникальные каталоги результатов и HTML report для каждого запуска;
- auth state по `ELEMENT_AUTH_STATE` либо существующему `.auth/user.json`,
  без чтения его содержимого; приложение без входа тоже поддерживается.

Первый переход — `page.goto(process.env.ELEMENT_APP_URL!)`. Не используй
`page.goto("/")`: он отбрасывает значимый `/applications/<name>` в URL.
CI добавляй, только если он нужен пользователю. В существующем config ограничь
необходимые overrides нужным проектом/сценарием.

Исключи из Git `.auth/`, `.test-data/`, `node_modules/`, `test-results/`, `playwright-report/`,
`blob-report/`, `.playwright-browsers/` и реальные каталоги локальных артефактов.
Проверь ignore rules. В consumer сохрани URL и локальные defaults так, чтобы
повторение выполнялось одной командой нужного spec (например, `npm run test:documents`).
Дай короткий README с командами сценария, входом при необходимости и путём к отчёту;
при создании данных опиши также подготовку и повторное чтение. Удали команды на удалённые
инспекторы. Язык интерфейса/locale закрепи по фактически наблюдённому UI.

## Locators и проверки

Подтверди locator на текущем UI. Предпочитай `getByRole`, `getByLabel`,
`getByPlaceholder`, scoped `getByText` или уже существующий `data-testid`.
Если семантики не хватает, используй узкий DOM-признак, проверенный на реальной
форме; объясни такой fallback комментарием. Не угадывай внутренние CSS-классы,
XPath, координаты или порядок элементов.

Ограничивай поиск активной формой/диалогом. Ожидай наблюдаемое состояние через
web-first assertions, а не `waitForTimeout`, произвольный sleep или скрытый retry.
Если проверяется сохранение, нажатая кнопка или «Сохранено» ещё не доказывают запись: закрой
форму и открой точную запись заново, затем сравни сохранённые значения.
Page Object нужен при реальном повторном использовании, а не для одного теста.

## Данные и повторение

Если сценарий может создать запись, открой [test-data.md](test-data.md): общий
файл задачи, режимы prepare/verify и пример независимых tests. Используй helpers
при выполнении их условий применимости; locators и бизнес-проверки остаются
в spec проекта. Проверкам без создания данных этот setup не требуется.
При изменении существующей записи зафиксируй её точный ID и ожидаемый результат,
после сохранения прочитай заново; создание дополнительных записей не требуется.

После подготовки выполни дословно команду повторения из README в новом shell
без временных export. Если нужны URL/browser defaults, сохрани их в consumer
или укажи прямо в команде. Команда на удалённый inspector не входит в результат.
