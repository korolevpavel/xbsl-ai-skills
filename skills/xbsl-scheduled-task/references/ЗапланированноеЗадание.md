# Спецификация: ЗапланированноеЗадание

## Назначение

Platform facts:

- `ВидЭлемента: ЗапланированноеЗадание` определяет проектный шаблон
  запланированного задания.
- `Ид` — UUID элемента проекта.
- `Имя` используется для формирования порождаемого типа задания.
- `ПредопределенноеЗадание` управляет созданием задания при обновлении проекта:
  `НеСоздавать`, `ЗапланироватьПриОбновленииПроекта`,
  `СоздаватьПриостановленноеПриОбновленииПроекта`.
- `Расписание` — массив групп свойств расписания. Для `Вид: Ежедневно`
  используются `ЗапуститьВ` и `ПериодПовтораДней`.
- Модуль элемента проекта должен содержать предопределенный
  `Обработчик()` без параметров; он вызывается при запуске задания.

Local conventions:

- Skill создает только `<Имя>.yaml` и одноименный `<Имя>.xbsl`.
- Для минимального ежедневного задания skill задает один элемент
  `Расписание[]` с `ПериодПовтораДней: 1`.
- Значение `ЗапуститьВ` записывай литералом времени `HH:MM` без кавычек,
  например `08:00`. Кавычки превращают значение в строку вместо типа `Время`.
- Принадлежность задания подсистеме задается размещением внутри ее каталога, а
  не значением `ОбластьВидимости`.
- Связь YAML и module companion задается одинаковым basename в одном каталоге
  подсистемы с `Подсистема.yaml`.

## Версия

- Минимальная версия платформы: 9.1+.

## YAML

Required:

```yaml
ВидЭлемента: ЗапланированноеЗадание
Ид: <UUID>
Имя: <ИмяЗадания>
ОбластьВидимости: ВПодсистеме
ПредопределенноеЗадание: ЗапланироватьПриОбновленииПроекта
Расписание:
    -
        Вид: Ежедневно
        ЗапуститьВ: 08:00
        ПериодПовтораДней: 1
```

Optional:

- `Описание` добавляй только по запросу пользователя.
- `Параметры[]` описывает параметры выполнения задания; каждый параметр имеет
  `Имя`, `Ид`, `Тип` и при необходимости `ЗначениеПоУмолчанию`.
- Если у параметра нет значения по умолчанию, то
  `ПредопределенноеЗадание` может быть только `НеСоздавать`.
- Свойства повторов, публикации, хранения результатов, регистрации событий и
  мобильного запуска добавляй только при явном запросе и сверке с источниками.

Negative:

- Не добавляй поле обработчика в YAML.
- Не создавай `ПредопределенноеЗадание` со значением, отличным от
  `НеСоздавать`, если у задания нет расписания.
- Не добавляй неподтвержденные свойства повторов, результатов или событий в
  минимальный YAML.
- Не добавляй `Ид` внутрь `Расписание[]`: источник ежедневного расписания
  описывает `ЗапуститьВ` и `ПериодПовтораДней`.

## UUID

Required:

- UUID получает сам объект `ЗапланированноеЗадание`.
- Если добавляешь `Параметры[]`, каждый параметр получает свой UUID в `Ид`.

Negative:

- `Расписание[]` не получает UUID.
- Companion `.xbsl` не получает YAML UUID.

## Imports и visibility

Required:

- `ОбластьВидимости` задавай явно. Для нового задания без межподсистемных
  ссылок используй `ВПодсистеме`.
- `Импорт` не нужен для минимального задания без параметров и внешних типов.

Optional:

- Если параметры ссылаются на типы из других пространств имен, добавь
  соответствующий `Импорт`.

Negative:

- Не поднимай `ОбластьВидимости` до `ВПроекте` без межподсистемной ссылки или
  явного требования пользователя.
- Не добавляй `Импорт` для встроенных скалярных типов.

## Companion artifacts

Required:

- `*.yaml` — описание `ЗапланированноеЗадание`.
- `*.xbsl` — одноименный модуль с `@Обработчик` и
  `метод Обработчик()` без параметров.

Optional:

- Дополнительных companion-файлов для минимального задания нет.

Negative:

- Отсутствующий `.xbsl` является ошибкой.
- Отсутствующий `Обработчик()`, другое имя метода или параметры у
  `Обработчик()` являются ошибкой.
- Не создавай второй YAML-способ указать обработчик.

## Генерация

Required:

- Прочитай этот reference перед созданием задания.
- Найди проект и его подсистемы через `xbsl-explore`.
- Если пользователь указал подсистему, используй только точное совпадение
  внутри выбранного проекта; отсутствие совпадения является блокирующим
  конфликтом независимо от числа других подсистем.
- Только если подсистема не указана, автоматически выбирай единственную. При
  нескольких подсистемах запроси выбор и не принимай `suggested_path` как
  неявное решение; при отсутствии подсистем остановись и предложи создать ее
  через `xbsl-subsystem-add`.
- Получи UUID объекта через `xbsl-uuid`.
- Проверь, что каталог подсистемы принадлежит выбранному проекту и содержит
  `Подсистема.yaml`.
- После выбора подсистемы проверяй конфликт имени в ее `objects`, а не по
  глобальному `conflict` другой подсистемы.
- Создай `<Имя>.yaml` и `<Имя>.xbsl` рядом в выбранной подсистеме.
- Перед записью сравни ожидаемый текст с существующими файлами.

Local conventions:

- Совпадающий существующий файл оставь без изменений.
- Отличающийся существующий файл не перезаписывай; остановись с диагностикой и
  запроси решение пользователя.
- Для времени запуска используй литерал `HH:MM` без кавычек.

Negative:

- Не генерируй бизнес-логику, если пользователь не описал действие задания.
- Не меняй сигнатуру `Обработчик()`.
- Не создавай файлы задания в корне проекта.
- Не перенаправляй выбранную подсистему по глобальному результату конфликта.
- Не создавай альтернативный reference в `xbsl-meta-add`.

## Валидация

Required:

- YAML содержит `ВидЭлемента: ЗапланированноеЗадание`, `Ид`, `Имя`,
  `ОбластьВидимости`, `ПредопределенноеЗадание` и `Расписание`.
- Для минимального ежедневного задания `Расписание[0].Вид` равно `Ежедневно`,
  `ЗапуститьВ` заполнен литералом `HH:MM` без кавычек,
  `ПериодПовтораДней` равен `1`.
- Родительский каталог YAML содержит `Подсистема.yaml` и принадлежит выбранному
  проекту.
- Рядом с YAML в том же каталоге существует одноименный `.xbsl`.
- В `.xbsl` есть `@Обработчик` и `метод Обработчик()` без параметров.
- YAML не содержит поля обработчика.

Negative:

- `missing_companion`.
- `handler_method_not_found`.
- `wrong_handler_name`.
- `handler_has_parameters`.
